# Vibe corrections log

**Verified:** 2026-11-16 (Mistral Vibe Code CLI ≥ 2.25.4; admin config min CLI 2.24.2 / VS Code extension 1.16; docs site main)

| Claim | Verdict | Correction |
|---|---|---|
| Vibe is Le Chat, Mistral's chatbot. | ⚠️ PARTIAL | “Vibe is Mistral's **unified agent** for productivity and coding tasks … available across web, mobile, your code editor, and your terminal.” Chat and Work merged into one experience on September 22; “Chat and Work are now one.” The harness documented here is Vibe Code, the coding mode. |
| Vibe Code asks for approval before every file edit. | ❌ FALSE | The default agent is `accept-edits`: “Auto-approves file edits in the working directory. Still asks for approval for other actions (for example, shell commands).” Only the `ask` agent prompts before every tool. |
| Vibe Code ships a built-in `plan` agent. | ❌ FALSE | “Vibe has no built-in `plan` agent. If your config sets `default_agent = "plan"` and you don't have a custom agent named `plan`, Vibe shows a warning and starts sessions with `ask` instead.” |
| Smart approve sandboxes the agent. | ❌ FALSE | “Smart approve is a classifier, not a sandbox. A call that it judges safe runs with the same access as your user account … it doesn't limit what the agent can do.” |
| The `auto-approve` agent is safe for general use. | ❌ FALSE | “this agent can run arbitrary commands such as `rm -rf` against any path Vibe can reach” — “Use **only in a trusted, sandboxed environment**,” and an administrator can disable it with `enable_auto_approve = false`. |
| MCP tools follow the `mcp__server__tool` naming convention. | ❌ FALSE | “MCP tools are addressed as `{server_name}_{tool_name}`” — a single underscore separates server and tool. |
| A skill's `allowed-tools` list is enforced. | ❌ FALSE | “`allowed-tools`: lists the tools the skill expects to use. Vibe reads this field but doesn't enforce it: a skill can call any tool the active agent allows.” |
| Admin config is a security control. | ❌ FALSE | “Admin config is a **distribution mechanism, not a security control** … users who control their local CLI environment can bypass them. Use it to set safe defaults, not to guarantee access rules.” |
| Project `.vibe/` configuration always loads. | ❌ FALSE | Project settings load “only when its folder is [trusted]”: “If you decline or have not yet trusted a directory, project-level configuration is ignored and Vibe prints a warning.” |
| Plugins are a stable interface. | ⚠️ PARTIAL | “Plugin support is experimental and under active development. The plugin format and the features on this page will change, and an update can break existing plugins.” |
| Claude Code plugins work in Vibe. | ⚠️ PARTIAL | Vibe reads “the Agent Plugins 1.0 format” with Vibe-specific parts in `ai.mistral.vibe/`, and “Hooks in plugins written for Claude Code or Kimi Code don't run: Vibe reports them as not supported.” |
| A Mistral API key is always required. | ⚠️ PARTIAL | “**Browser-based sign-in is enabled by default** when your config targets a model with a Mistral provider … no API key is needed for typical Mistral-provider setups.” Keys matter for non-Mistral providers, automation, and custom keys. |
| Vibe Code Web runs against your local checkout. | ❌ FALSE | “Run Vibe Code … against a GitHub repository in a remote sandbox via Vibe Code Web.” “The sandbox **cannot reach your local machine**. The agent works from the repository, the default image, and outbound network calls.” |
| The cloud sandbox has unrestricted network access. | ⚠️ PARTIAL | “The sandbox has **outbound internet access managed by Mistral** … Inbound access from the public internet to the sandbox is not exposed,” and outbound calls are rate-limited. |
| Cloud session work survives in the sandbox. | ⚠️ PARTIAL | “The sandbox is deleted when the session ends … Anything that must survive the session has to be committed to the repository.” |
| Legacy `~/.vibe/tools/` Python tools still load. | ❌ FALSE | “Vibe no longer loads custom Python tools from `~/.vibe/tools/` or `./.vibe/tools/`, and shows a warning at startup for each file there. To keep a tool, ask Vibe to turn it into a [skill].” |
| The Mistral Code Enterprise JetBrains plugin is the supported IDE path. | ❌ FALSE | “**Don't use the Mistral Code Enterprise JetBrains plugin.** It's deprecated … The supported path is to run Vibe through ACP” (`vibe-acp`), including JetBrains AI Assistant. |
| Vibe silently reads `.env` and `.envrc` files. | ❌ FALSE | “It also asks before a tool reads or edits `.env` and `.envrc` files, even when the tool's permission is `always`. A path listed in the tool's `allowlist` skips both checks.” |
| The built-in tools are named `read` and `search_replace`. | ⚠️ PARTIAL | Renamed: “`read` is now `read_file`, and `search_replace` is now `edit`. Vibe migrates the old names in your configuration files automatically.” |
| Vibe Code Web sandboxes are shared infrastructure. | ❌ FALSE | “The sandbox is single-tenant for the duration of the session: nothing from your other sessions or other users runs in it … The sandbox is deleted when the session ends.” |
| Project hooks.toml entries always apply. | ⚠️ PARTIAL | Project-level hooks load “**trusted folders only**”; when the same `name` appears in both files, “the **project entry wins**,” and “Subagents inherit the parent's hook configuration, so policies apply transitively.” |
| Org and Workspace admin configs merge. | ❌ FALSE | “The server doesn't merge the two configurations.” A Workspace can inherit the Organization config, “replace it with its own” (“Settings defined only at the Organization level don't apply”), or disable admin config entirely. |
| Vibe implements plan mode like peer harnesses. | ❌ FALSE | No built-in plan mode; the docs steer you to “create your own plan agent,” and best practice is to “Start in `ask` or a plan agent for unfamiliar code.” |
| Session titles and compaction use the session model only. | ❌ FALSE | “`[utility_models]`” holds models for background tasks — “the smart approve classifier and session titles” — and “`compaction_model`” can be set separately, though it “Must use the active model's provider.” |
| Programmatic runs still prompt for approval. | ❌ FALSE | “In **programmatic mode** (`vibe --prompt …`) … Nobody can answer an approval prompt, so Vibe denies every tool call that needs approval. Pass `--auto-approve` (or `--yolo`) to approve every tool call.” Also, “**Programmatic mode never prompts for trust.**” |
| The Lean 4 agent works out of the box. | ⚠️ PARTIAL | The `lean` agent ships in the agent list but “Install with `/leanstall` from inside the CLI, and remove it with `/unleanstall`.” |
| Vibe Code Web sessions can run indefinitely. | ⚠️ PARTIAL | “The loop continues until the task reaches a natural stopping point, the agent asks a question, or a limit is reached” — limits are documented on the Limits and lifecycle page. |
| Tool names in permission tables are matched exactly only. | ⚠️ PARTIAL | Tool and skill filters support “**exact names**, **glob patterns**, and **regex** with the `re:` prefix”. Precedence differs by surface: `disabled_tools` is “applied after `enabled_tools`”, while `disabled_skills` is “applied when `enabled_skills` is empty” — a non-empty `enabled_skills` ignores it. |
