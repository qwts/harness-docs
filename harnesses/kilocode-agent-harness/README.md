# Kilo Code harness

**Verified:** 2026-11-15 against the official Kilo Code documentation at kilo.ai/docs (Kilo / Anaconda)
**Status:** Reference documentation, not a runtime conformance audit
**Primary scope:** `kilo` CLI (TUI, `kilo run`, serve/ACP), VS Code extension (`kilocode.kilo-code`) with embedded runtime, JetBrains v7 plugin, Desktop, `~/.config/kilo/` and project `kilo.jsonc` configuration, agents and permission engine, sandbox, skills/MCP/plugins, Agent Manager worktrees, Cloud Agents, AI Code Reviews, Kilo Gateway
**Provenance:** Official Kilo sources unless explicitly marked otherwise

Kilo Code (published by Kilo — the product rebranded from kilocode.ai to kilo.ai following the Anaconda acquisition) is a multi-surface coding agent: a VS Code extension that bundles its own runtime, a standalone CLI that is "a fork of OpenCode," a native JetBrains plugin, a Desktop app, and cloud/mobile clients. All surfaces share one `kilo.jsonc` configuration system (global `~/.config/kilo/`, project root or `.kilo/`), one agent/permission model (built-in `code`/`ask`/`plan`/`debug` agents plus frontmatter-defined custom agents, last-match-wins `allow`/`ask`/`deny` rules), and one instruction stack (`AGENTS.md` primary, `.kilo/rules/*.md` via the `instructions` key). Model traffic routes through the OpenAI-compatible Kilo Gateway (`ai-gateway.kilo.ai/api/v1`) with `kilo-auto/frontier|efficient|free` virtual tiers, BYOK support that "does not fall back to using Kilo's keys," and microdollar-precision billing. An opt-in OS sandbox (macOS/Linux only) defaults its network policy to deny, an Agent Manager panel orchestrates worktree-per-task sessions with a Swarm message board, and cloud Review Agents post AI reviews to GitHub/GitLab PRs governed by a base-branch `REVIEW.md`. The `kilocode` registry identity normalizes to this single harness.

## Top corrections

- ❌ **“Kilo prompts for every tool call out of the box.”** “Most tools default to `"*": "allow"` for a smooth out-of-the-box experience” — the prompt-by-default exceptions are `.env` reads, `external_directory`, `doom_loop`, and the JetBrains plugin’s `edit`; only a rule-free fallback is ask. Kilo’s own older “How Tools Work” page still claims otherwise.
- ❌ **“The sandbox keeps code away from the model provider.”** “The network sandbox is not a provider privacy control. Provider and model inference traffic remains available.” If Kilo reads a secret into context, “that content may be sent to the configured model provider even while network restriction is on.”
- ❌ **“Kilo silently falls back when a BYOK key or sandbox policy fails.”** “If the key is invalid, the request fails. It does not fall back to using Kilo's keys”; an unenforceable sandbox policy means Kilo “refuses to run the affected tool. It does not silently fall back to unrestricted execution.”
- ❌ **“Permission rules are first-match-wins.”** “When more than one rule matches the requested permission and target pattern, the last matching rule wins” — and a compound bash block requires every parsed command to be permitted.
- ❌ **“Kilo ships built-in orchestrator and review agents.”** Orchestrator is deprecated (“Agents with full tool access (Code, Plan, Debug) now support subagents natively”), and “The VSCode extension and CLI do not include a built-in Review agent.”
- ❌ **“SSE is the transport to configure for remote MCP.”** SSE is “deprecated as of MCP specification version 2025-03-26”; Kilo “tries StreamableHTTP first, then falls back to SSE automatically.”
- ❌ **“Skills from the repo can run their embedded shell commands.”** Commands execute only from trusted locations — “Project skills (.kilo/skills/ in a repository) and skills fetched from remote URLs never execute commands.”
- ❌ **“Non-interactive `kilo run` waits for approvals.”** “Without --auto, a non-interactive run cannot prompt for approval and auto-rejects any permission request it receives,” exiting 1 if anything was rejected; `--auto` is flagged “(dangerous!)”.
- ❌ **“REVIEW.md is read from the feature branch being reviewed.”** “Kilo reads REVIEW.md from the PR/MR base branch, not the feature branch. That prevents an unreviewed change from rewriting the review policy used to evaluate itself.”
- ❌ **“Checkpoints are permanent history.”** “A background process runs git gc --prune=7.days every hour,” and snapshots are “raw tree hashes (not refs or commits),” so old snapshots can be garbage-collected while a session still references them.
