# Kilo Code corrections log

**Verified:** 2026-11-15

| Claim | Verdict | Correction |
|---|---|---|
| Kilo Code is a VS Code extension only. | ❌ FALSE | Kilo ships a VS Code extension, a standalone CLI (`npm install -g @kilocode/cli`), a native JetBrains plugin (v7, 9 IDEs), a Desktop app, Cloud Agents, and Mobile clients. |
| Kilo's documentation lives at kilocode.ai/docs. | ❌ FALSE | The product has rebranded to Kilo (kilo.ai) — kilocode.ai/docs issues a 308 redirect and the canonical pages serve from kilo.ai/docs. An Anaconda-acquisition banner appears on the site. |
| The VS Code extension requires a separate Kilo CLI install. | ❌ FALSE | “The extension includes its own embedded runtime. No separate Kilo CLI installation is required” — it “starts its embedded runtime from the extension and applies the relevant VS Code network settings to that runtime.” |
| The Kilo CLI is original, Kilo-only code. | ⚠️ PARTIAL | The CLI is packaged from Kilo-Org/kilocode, but “The Kilo CLI is a fork of OpenCode and supports the same configuration options,” and npm plugin caches even live under `~/.cache/opencode/packages/`. |
| The orchestrator agent is a supported built-in workflow. | ❌ FALSE | “Orchestrator is deprecated and will be removed in a future release. Agents with full tool access (Code, Plan, Debug) now support subagents natively — there's no need for a dedicated orchestrator.” |
| Kilo ships a built-in Review agent. | ❌ FALSE | “The VSCode extension and CLI do not include a built-in Review agent. Code review workflows can be handled by the code agent or via custom agent configurations.” (The cloud Review Agent for PRs is a separate product.) |
| No tools are auto-approved out of the box — every tool call prompts. | ❌ FALSE | The Auto-Approve reference states “Most tools default to `"*": "allow"` for a smooth out-of-the-box experience,” with named exceptions (.env reads, `external_directory`, `doom_loop`, JetBrains-plugin `edit`). Kilo's own older “How Tools Work” page contradicts this with “No tools are auto-approved out of the box” — a doc-vs-doc inconsistency; the current settings reference wins. |
| When no permission rule matches, Kilo allows the call. | ❌ FALSE | “When no rule matches a permission check, the default action is ask.” The allow-by-default behavior comes from shipped wildcard rules, not from the fallback. |
| Permission rules are first-match-wins. | ❌ FALSE | “Permission rules are evaluated in config order. When more than one rule matches the requested permission and target pattern, the last matching rule wins.” |
| A broad `read: allow` rule covers reading `.env` files. | ❌ FALSE | “.env and .env.* reads as sensitive. Broad read approvals, such as read: allow, `read: { "*": allow }`, saved wildcard approvals, or allow-everything mode do not bypass the built-in prompt for these files. .env.example is treated as safe documentation and can be allowed by default.” |
| A bash allow rule covers every command in a compound shell block. | ❌ FALSE | “The bash permission is checked against parsed shell command patterns. If a shell block contains multiple parsed commands, each relevant command must be permitted. A single denied command rejects the request.” Commands are parsed with Tree-sitter, so path and external-directory checks apply to parsed intent. |
| The OS sandbox is enabled by default. | ❌ FALSE | “The sandbox is disabled by default.” |
| The sandbox blocks the agent from reading files. | ❌ FALSE | “It does not restrict filesystem reads. An agent can still read any file that your user account can read, but it can write only to explicitly allowed locations.” |
| Sandboxing works on Windows. | ❌ FALSE | “Sandboxing is not available on Windows.” |
| If a sandbox policy cannot be enforced, Kilo silently runs unrestricted. | ❌ FALSE | “If an enabled macOS or Linux sandbox policy cannot be enforced, Kilo reports the reason and refuses to run the affected tool. It does not silently fall back to unrestricted execution.” |
| `sandbox.allowed_hosts` and `sandbox.writable_paths` can be set in project config. | ❌ FALSE | They are global-config-only; a project config may tighten the policy but cannot widen it. |
| The sandbox's network policy fully contains MCP integrations. | ⚠️ PARTIAL | While network restriction is active, “local and remote MCP tool calls and typed resource reads are unavailable, but MCP prompt retrieval remains outside the session network policy,” and “MCP client lifecycle and plugin hooks run as trusted host integrations.” |
| The network sandbox prevents secrets from reaching the model provider. | ❌ FALSE | “The network sandbox is not a provider privacy control. Provider and model inference traffic remains available. If Kilo reads a secret and includes it in a prompt, tool result, or conversation context, that content may be sent to the configured model provider even while network restriction is on.” |
| Sandboxed commands can run `git commit` in a managed worktree without prompting. | ❌ FALSE | “.git directories are always read-only to sandboxed tools,” and in a linked worktree “the .git file points into the parent repository's .git directory. That directory is outside the worktree, so the write is outside the sandbox write boundary” — mutating git commands prompt; “Read-only git commands, such as git status or git log, do not trigger the prompt.” |
| Auto Model tiers map to fixed underlying models. | ❌ FALSE | “The underlying models behind each tier are updated server-side as better options become available or as providers change pricing” — kilo.ai/models carries live assignments. |
| Auto Free is safe for confidential code because it costs nothing. | ❌ FALSE | Auto Free “rotates through available free models,” and NVIDIA free endpoints carry a “Trial use only - do not submit personal or confidential data” warning: session data is logged for NVIDIA's purposes. |
| An invalid BYOK key silently falls back to Kilo's own keys. | ❌ FALSE | “If the key is invalid, the request fails. It does not fall back to using Kilo's keys.” |
| Kilo marks up gateway inference costs. | ❌ FALSE | “Model inference is deducted from your balance at the upstream provider's rate with no markup,” and “Kilo is not currently charging a payment-processing fee when you purchase Kilo credits.” |
| Kilo credits never expire. | ❌ FALSE | “Paid purchases expire one calendar year after purchase,” including Kilo Pass allotments. |
| Gateway billing granularity is whole cents. | ❌ FALSE | The gateway tracks “microdollar precision (1 USD = 1,000,000 microdollars)” with atomic per-request balance updates. |
| A zero balance only slows Kilo down. | ❌ FALSE | Paid-model requests return HTTP 402 with a `buyCreditsUrl` metadata link — a hard stop. |
| MCP server timeout defaults are documented as one value for all surfaces. | ⚠️ PARTIAL | The extension page says “The default is 10 seconds for local servers and 15 seconds for remote servers”; the CLI page documents a 5,000 ms default for tool fetching on both transports. The values differ by surface and page. |
| MCP servers are configured in a Claude-style `mcpServers` JSON block. | ❌ FALSE | Kilo configures servers under the `mcp` key in `kilo.jsonc` (global `~/.config/kilo/` or project root/`.kilo/`), with `type: "local"`/`"remote"` entries. |
| SSE is the recommended remote MCP transport. | ❌ FALSE | “The SSE Transport has been deprecated as of MCP specification version 2025-03-26”; Kilo “tries StreamableHTTP first, then falls back to SSE automatically.” |
| Skill-embedded shell commands run wherever the skill is stored. | ❌ FALSE | “Commands execute only in skills from trusted locations: global skills (such as ~/.kilo/skills/, ~/.agents/skills/, and ~/.claude/skills/), skills built into Kilo Code, and absolute skill paths declared in global config. Project skills (.kilo/skills/ in a repository) and skills fetched from remote URLs never execute commands.” |
| Skill shell commands run silently once bash is auto-approved. | ❌ FALSE | “When the agent loads a trusted skill containing commands, every command in the file is listed in a single permission prompt before anything runs. Approving runs all of them; rejecting aborts the skill load. This prompt appears even when bash commands are otherwise auto-approved, and a deny rule on any command still blocks it.” `KILO_DISABLE_SKILL_SHELL` disables the feature entirely. |
| npm plugin install scripts run normally. | ❌ FALSE | “Kilo installs packages with lifecycle scripts such as install and postinstall blocked.” |
| `.mcp.json`-style plugins install into the project's node_modules. | ❌ FALSE | npm plugins are cached under the CLI XDG cache — “`~/.cache/opencode/packages/` by default” — installed with Bun, deduplicated across levels. |
| `agents.md` (lowercase) works as the instructions filename. | ❌ FALSE | “The filename must be uppercase ( AGENTS.md ), not lowercase ( agents.md ). This ensures consistency across different operating systems and tools.” `AGENT.md` is the singular fallback. |
| Per-directory AGENTS.md files are pre-loaded at session start. | ❌ FALSE | They are “dynamically loaded when the agent reads files in that directory - they are not pre-loaded at session start,” injected “as <system-reminder> tags.” |
| AGENTS.md supersedes CLAUDE.md and CONTEXT.md — you must pick one. | ❌ FALSE | All three are read from the project root: AGENTS.md primary, CLAUDE.md “Also supported for compatibility,” CONTEXT.md “Additional project context.” |
| The `~/.claude/CLAUDE.md` global fallback is permanent. | ❌ FALSE | It applies “until Claude Code Migration has been attempted. Migration ends this global fallback; project-level CLAUDE.md files keep working.” |
| Rules dropped in `.kilo/rules/` load automatically. | ❌ FALSE | Custom rules only take effect when their paths or globs are referenced from the `instructions` array in kilo.jsonc; the format is deliberately “Plain Markdown files—no YAML frontmatter or GUI configuration required.” |
| AGENTS.md is just another editable file the agent may rewrite. | ❌ FALSE | “Both AGENTS.md and AGENT.md are write-protected files in Kilo Code” — the agent cannot modify them “without explicit user approval.” |
| Kilo's memory is on by default and roams across projects. | ❌ FALSE | Memory is opt-in and project-only, stored under `~/.local/share/kilo/memory/<project-slug>-<sha1-12>/` with project/environment/corrections files and per-session digests. |
| `.kilocodeignore` is the primary file-access mechanism. | ❌ FALSE | “The primary mechanism for controlling file access is the permission system in kilo.jsonc.” The IgnoreMigrator “automatically converts .kilocodeignore patterns into permission deny rules on read and edit tools.” |
| Everything under `node_modules` and friends is blocked by config. | ⚠️ PARTIAL | Those directories never reach the config layer at all: “Hardcoded directory ignores — 27 directories are always skipped,” plus “11 file patterns are always skipped (e.g. lock files, binary artifacts).” |
| Compaction triggers only when a percentage of the window is consumed. | ❌ FALSE | “Compaction runs when either count reaches compaction.threshold_percent, or when the remaining window hits the reserved safety buffer, whichever happens first.” |
| Context pruning rewrites older assistant messages. | ❌ FALSE | The prune pass “walks completed tool outputs outside a 40,000-token recency window and replaces them with `"[Old tool result content cleared]"`” — tool outputs, not assistant turns. |
| The reserved compaction buffer applies to every model. | ❌ FALSE | “Applies only to models that advertise a separate input limit; models with a single context window use their full output cap as the reserve instead.” |
| Codebase indexing runs by default. | ❌ FALSE | It is opt-in and “disabled by default,” requiring an embedding provider and vector store (LanceDB default, Qdrant optional). |
| Non-interactive `kilo run` pauses for permission prompts. | ❌ FALSE | “Without --auto, a non-interactive run cannot prompt for approval and auto-rejects any permission request it receives. If a run auto-rejected at least one request, it exits 1 with a stderr diagnostic naming the cause.” |
| `--auto` is a routine convenience flag. | ❌ FALSE | The CLI reference labels it “auto-approve permissions that are not explicitly denied (dangerous!)”. |
| `kilo run` accepts `--org`/`--team` flags. | ❌ FALSE | “There is no --org or --team flag on kilo run.” Organization comes from `KILO_ORG_ID` or the persisted last `/teams` selection. |
| `kilo console` is Kilo's primary web UI. | ❌ FALSE | “The kilo console command and its browser interface are deprecated and will be removed in a future release.” |
| `/reload` can run while a session is executing. | ❌ FALSE | “Kilo refuses the reload while any session in the project is running; wait for it to finish or abort it first.” |
| Agent Manager worktrees are ad-hoc temp directories. | ❌ FALSE | “Managed worktrees are created under .kilo/worktrees/ in your project. Kilo also stores Agent Manager UI state in .kilo/agent-manager.json.” |
| Worktree setup scripts must be chmod +x. | ❌ FALSE | Kilo runs them with `sh`, PowerShell, or `cmd.exe` by file extension, “so executable permissions are not required.” They carry a five-minute timeout, with `WORKTREE_PATH`/`REPO_PATH` injected. |
| Kilo copies every `.env` file into new worktrees. | ⚠️ PARTIAL | “Kilo automatically copies root-level .env files from the main repo into the new worktree” — exactly `.env` and root-level `.env.*`. “Nested env files, such as apps/web/.env.local” and “Non-dotenv files, such as .envrc” are not copied. |
| `board_post` wakes or notifies the recipient agent. | ❌ FALSE | Every post returns the receipt “Stored only. This does not confirm delivery, reading, or action, and does not wake recipients,” and “Swarm does not start, stop, or assign agents.” |
| Approving the `agent_manager` tool once covers all future panel actions. | ❌ FALSE | “Approval prompts are scoped to the requested capability, so approving worktree does not automatically approve local, an overview, or a targeted prompt”; stopping, moving, and answering “each require their own approval.” |
| Multi-version worktrees move between sections independently. | ❌ FALSE | “Multi-version worktrees (created via Multi-Version Mode) are moved together — assigning one version to a section moves all versions in the group.” |
| Cloud Agents work with personal Bitbucket accounts. | ❌ FALSE | “Bitbucket repositories are available for organizations only.” |
| REVIEW.md is read from the PR's feature branch. | ❌ FALSE | “Kilo reads REVIEW.md from the PR/MR base branch, not the feature branch. That prevents an unreviewed change from rewriting the review policy used to evaluate itself.” |
| REVIEW.md of any length is applied in full. | ❌ FALSE | “If it is longer than 10,000 characters, Kilo truncates it and notes that in the review summary footer.” |
| Free models lift the concurrent-review limit. | ❌ FALSE | Concurrency follows balance, not model cost: personal ≤$5 → 1, above $5 → up to 3 (“A funded personal account running a free model still gets 3 concurrent reviews”), organizations up to 20. |
| Kilo's GitHub bot handle is @kilo. | ❌ FALSE | It is @kilocode-bot, requiring both the KiloConnect App and the Kilo Code Bot App; the docs' troubleshooting explicitly says to check you are “mentioning @kilocode-bot (not @kilo )”. |
| Code review sub-agent counts are configurable only in REVIEW.md. | ⚠️ PARTIAL | Defaults are tiered by diff size (“the largest tier triggered by either signal”: ≤2 files & <100 lines → 0; 3–5 files or 100–300 → ≤1; 6+ files or >300 → 6 sharded), and “REVIEW.md can replace the default sub-agent guidance.” |
| Checkpoint snapshots are kept forever. | ❌ FALSE | “A background process runs git gc --prune=7.days every hour”; snapshots are “raw tree hashes (not refs or commits),” so “older snapshots may be pruned by garbage collection even if a session still references them.” |
| MCP tool permissions use bare tool names. | ❌ FALSE | Keys are namespaced `{server}_{tool}` (e.g. `github_create_pull_request`), with glob patterns like `github_*` supported. |
| The JetBrains plugin requires Node.js like older versions. | ❌ FALSE | “Kilo Code v7 for JetBrains is officially available. It uses a native JetBrains interface, works well in remote development split mode, and does not require Node.js.” |
| Autocomplete runs on your selected chat model. | ❌ FALSE | “Autocomplete uses Codestral ( mistralai/codestral-2508 ) by Mistral AI, billed through your Kilo account” — routed through the gateway unless Mistral BYOK is attached. |
| The Cmd+L autocomplete trigger works out of the box. | ❌ FALSE | “This keybinding requires kilo-code.new.autocomplete.enableSmartInlineTaskKeybinding to be enabled in VS Code settings. It is disabled by default.” |
| Project kilo.jsonc edits hot-reload like global ones. | ❌ FALSE | Project config is cached at workspace load and needs a window reload; global config auto-reloads. |
| Shell execution relies on VS Code's terminal shell integration. | ❌ FALSE | “Instead of relying on VS Code's terminal shell integration, the CLI spawns and manages shell processes directly using the bash tool” — and “The interactive_terminal tool, the in-session terminal controls, the related API endpoints, and the matching SDK types were removed.” |
| Kilo's default bash timeout is unbounded. | ❌ FALSE | The bash tool carries a per-command timeout “defaults to 2 minutes,” with a `workdir` parameter replacing `cd &&` chains. |
| The gateway is required for all Kilo usage. | ❌ FALSE | BYOK provider keys, subscription-based providers, and local runtimes (Ollama, LM Studio, Atomic Chat) all route outside Kilo's gateway billing. |
| `.kilocoderules`, `custom_modes.yaml`, and `.kilocodemodes` are dead formats. | ❌ FALSE | They are legacy-supported via auto-migration, with the old `build`/`architect` agents renamed to `code`/`plan`. |
| Kilo Gateway keys are stored in plaintext. | ❌ FALSE | “Keys are encrypted at rest using AES-256 encryption” — API keys are “JWT tokens tied to your Kilo account.” |
| Organization members can hide organization-managed agents. | ❌ FALSE | “Individual members cannot remove organization-managed agents from their local agent list. Changes need to be made in the organization-managed definition” — and such agents may shadow built-ins by name. |
| Anonymous gateway use requires an account. | ❌ FALSE | Free models are “available to both authenticated and anonymous users. Anonymous users are rate-limited to 200 requests per hour per IP address,” and the models endpoint needs no auth. |
