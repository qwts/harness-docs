# Pi corrections log

**Verified:** 2026-11-16 (Pi v1.5.2)

| Claim | Verdict | Correction |
|---|---|---|
| Pi asks for approval before running commands. | ❌ FALSE | “Pi shows each file read, search, command, and edit it performs. It does not ask before every tool call.” The usage page adds: “Review commands and changed files, and use a sandbox for untrusted or unattended work.” |
| Pi has permission modes like Ask/Auto/Full. | ❌ FALSE | No approval-mode system exists in the documentation. Control is tool selection (`--tools`, `defaultTools`), extension `tool_call` gates, and external isolation. |
| Project trust sandboxes tool calls. | ❌ FALSE | “Project trust does not limit what tool calls can access or affect. After Pi starts, enabled tools still use the operating-system permissions of the Pi process.” |
| Declining project trust stops Pi from reading the folder's instructions. | ❌ FALSE | “Context files such as `AGENTS.override.md`, `AGENTS.md`, and `CLAUDE.md` load regardless of project trust unless you disable context loading. Treat instructions in a folder as untrusted input even when you decline project trust.” |
| Pi is Inflection's Pi assistant. | ❌ FALSE | Pi is “a minimal, extensible agent harness that you can make your own” from Earendil Works (`earendil-works/pi`, formerly under the `badlogic` organization — the docs still link `badlogic/pi-skills`). |
| Pi ships with sub-agents and plan mode. | ❌ FALSE | “Pi ships with powerful defaults but skips features like sub-agents and plan mode. Ask Pi to build what you want, or install a package that does it your way.” |
| Pi supports ACP clients such as Zed or Omnigent. | ❌ FALSE | No ACP surface appears in the docs; machine integration is print mode, JSON mode, RPC mode, and the TypeScript SDK. The only Zed reference is “Zed integrated terminal” keybindings. |
| The npm install runs lifecycle scripts. | ❌ FALSE | “Pi does not require dependency lifecycle scripts for a normal npm installation” — the documented command is `npm install -g --ignore-scripts @earendil-works/pi-coding-agent`. |
| `pi update` upgrades every installation. | ❌ FALSE | “`pi update` cannot update Pi when another package manager provides it, such as Nix. Update Pi with that package manager, for example `nix profile upgrade pi`.” Wrappers can set `PI_SELF_UPDATE_COMMAND` or `selfUpdateCommand`. |
| Uninstalling Pi removes sessions and credentials. | ❌ FALSE | “None of these methods removes configuration, credentials, sessions, or installed Pi packages from `~/.pi/agent/`.” |
| Environment variables are the first credential source. | ❌ FALSE | “Pi uses a runtime `--api-key` first, then a stored `auth.json` credential, an `apiKey` from `models.json`, and finally the provider's environment variables or ambient cloud credentials.” |
| API keys are stored in `settings.json`. | ❌ FALSE | “Pi stores credentials in `auth.json`”; `models.json` `apiKey` entries are an additional source, and `auth.json` `key` accepts a `!command` for secret managers. |
| `pi auth logout` also unsets environment variables. | ❌ FALSE | “This does not unset environment variables, remove authentication from `models.json`, or revoke the credential at the provider.” |
| The default thinking level is `off` or `max`. | ❌ FALSE | `defaultThinkingLevel` defaults to `"medium"`; `--thinking` accepts `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max` and “is clamped to the model's capabilities.” |
| Sessions are one linear transcript. | ❌ FALSE | “Messages and events in a session form a tree. Each path through that tree is a branch. The branch ending at the current entry is the active branch.” |
| Compaction deletes the original conversation. | ❌ FALSE | “Compaction adds a summary and keeps recent messages. It does not delete the original session entries”; repeated compaction summarizes from the previous `firstKeptEntryId`. |
| Branching erases the abandoned path. | ❌ FALSE | “Pi stores entries as a tree, so returning to an earlier point does not erase the branch you leave.” |
| `--session-id` opens any directory's session. | ❌ FALSE | It “opens the current directory's existing session with the ID, or creates it otherwise”; `--session` by ID from another directory “offers to fork it into the current directory instead.” |
| Sessions are grouped by model. | ❌ FALSE | They are stored “under `~/.pi/agent/sessions/`, grouped by working directory.” |
| `pi -p` exits 0 even when the run fails. | ❌ FALSE | “A final assistant response with an `error` or `aborted` stop reason produces a nonzero exit status,” and a `length` cut-off “produces a nonzero exit status” with partial text. |
| JSON mode emits one JSON result object. | ❌ FALSE | It writes “a session header followed by agent and session events as newline-delimited JSON,” and “A failed or aborted assistant response appears in the event stream but does not by itself produce a nonzero exit status.” |
| A successful RPC `prompt` response means the run finished. | ❌ FALSE | “It does not mean the run completed. Continue consuming events through `agent_settled` when completion matters.” |
| MCP servers can use the SSE transport. | ❌ FALSE | “`sse` is rejected. Servers that document an SSE endpoint often also provide streamable HTTP, commonly at `/mcp` instead of `/sse`.” |
| MCP tools are declared to the model by default. | ❌ FALSE | Default exposure is `codemode` — “neither declared to the model nor listed in the codemode description”; only `direct` exposure declares a tool. |
| `--tools read,bash` removes MCP tools. | ❌ FALSE | “`--tools` does not remove MCP tools unless one of its entries starts with `mcp__`”; use `--exclude-tools 'mcp__*'` or `--no-mcp` to remove them. |
| MCP OAuth callbacks must be HTTPS. | ❌ FALSE | a `callbackUrl` “must use HTTP on `localhost`, `127.0.0.1`, or `[::1]`”; only `authServerMetadataUrl` carries the HTTPS-with-loopback-exception rule. |
| Project `.pi/mcp.json` loads without trust. | ❌ FALSE | “Project configuration is read only after project trust is granted,” and “Project `.pi/mcp.json` files are only read for projects that are already trusted.” |
| Everything under `.pi/` is trust-gated. | ⚠️ PARTIAL | Protected resources are the listed ones (`.pi/settings.json`, `mcp.json`, resource dirs, `SYSTEM.md`/`APPEND_SYSTEM.md`, project `.agents/skills`); “A bare `.pi` directory does not require project trust,” and “Pi reads the project `sessionDir` setting … before it resolves project trust.” |
| `defaultProjectTrust` can be set per project. | ❌ FALSE | The settings table marks it “**Can only be set in agent-directory settings.**” |
| Codemode scripts get filesystem and network access. | ❌ FALSE | “It runs as the body of an async function in a QuickJS sandbox … The sandbox has no Node APIs, file system, network, or timers; scripts reach the outside world only through tools and `models`.” |
| Codemode is enabled by default. | ❌ FALSE | Default `defaultTools` is `read`, `bash`, `edit`, `write`; `codemode` is “off by default; the MCP extension turns them on when an MCP server needs them” — enable with `"defaultTools": ["+codemode"]` or `--tools +codemode`. |
| Skills load their full instructions at startup. | ❌ FALSE | “Pi scans configured skill locations and adds each skill's name, description, and path to the system prompt. It does not add the full instructions. When a task matches, the model reads `SKILL.md`.” |
| A skill's declared name must match its directory. | ⚠️ PARTIAL | “Pi neither requires nor warns when the declared name differs from the parent directory. Other Agent Skills implementations may enforce that requirement, so matching names remain the portable choice.” |
| Prompt templates can execute code. | ❌ FALSE | They expand Markdown into text (“Pi expands the template before the resulting text enters the agent”); executable behavior requires extensions. |
| Package `devDependencies` are installed. | ❌ FALSE | “Put runtime packages imported by extensions in `dependencies` … `devDependencies` are not installed,” and host-provided packages belong in `peerDependencies` — “Do not list host-provided packages in `dependencies`.” |
| Extension discovery walks the whole tree. | ❌ FALSE | “Discovery goes one level deep. Larger packages declare their entry points in a `package.json` manifest.” |
| Extensions run in a sandbox. | ❌ FALSE | “An extension runs inside the Pi process with the same operating-system permissions. It can inspect prompts, tool calls, files, credentials, and session history, so load extensions only from sources you trust.” |
| `/share` is always a private gist. | ⚠️ PARTIAL | “By default, Radius authentication makes the artifact visible to your Radius organization; otherwise, Pi creates a private GitHub gist”; `sessionShareDestination` forces either. |
| Shell tools inject `PI_SESSION_*` into `!` commands. | ❌ FALSE | “These variables are injected into the LLM-callable `bash` and `powershell` tools. They are not injected into user-entered `!` or `!!` commands.” |
| Pi enables install telemetry only if you opt in. | ⚠️ PARTIAL | `enableInstallTelemetry` defaults to `true` (“anonymous install/update reporting and selected provider attribution headers”); it is `enableAnalytics` — “Opt in to analytics data sharing” — that defaults to `false`. |
| Custom tools that edit files are safe to run in parallel. | ❌ FALSE | “If your custom tool mutates files, use `withFileMutationQueue()` so it participates in the same per-file queue as built-in `edit` and `write`” — otherwise “whichever write lands last overwrites the other.” |
| Tool calls always run sequentially. | ❌ FALSE | “Tool calls from one assistant message run in parallel by default. Set `executionMode: "sequential"` when a tool must not run concurrently with other calls.” |
| Unregistering a tool removes it. | ❌ FALSE | “`hidden`: registered but unreachable. Re-register a tool with `exposure: "hidden"` to withdraw it, since tools cannot be unregistered.” |
