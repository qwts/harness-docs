# Surfaces: CLI, TUI, headless, ACP, and enterprise

**Verified:** 2026-11-15

## Install and login

Install is `curl -fsSL https://x.ai/cli/install.sh | bash`; the enterprise page lists `npm install -g @xai-official/grok` as an alternative that avoids the `x.ai` and `storage.googleapis.com` installer hosts. First launch “opens a browser for authentication. In non-browser environments, use an API key: `export XAI_API_KEY="xai-..."`.”

Four auth methods: Browser OIDC (`grok login`, refreshable), Device code (`grok login --device-auth`, RFC 8628, for “SSH sessions, containers, headless hosts”), External auth provider (`[auth] auth_provider_command` — a command printing a bare token or JSON `{"access_token", "refresh_token", "expires_in"}`; Grok sets `GROK_AUTH_EXPIRED=1` on background refreshes — “nobody is watching, and the command has a few seconds before Grok kills it — so mint silently or exit non-zero, never wait for input” — and unset on sign-in, where “there are up to 300 seconds for a browser round trip”), and API key (`XAI_API_KEY` or `model.api_key`, “No” refresh). Enterprise OIDC configures `[auth.oidc] issuer`/`client_id` (PKCE, refresh tokens) or `GROK_OIDC_ISSUER`/`GROK_OIDC_CLIENT_ID`. Login policies in `requirements.toml`: `disable_api_key_auth` (“forces interactive IdP login… a leftover `XAI_API_KEY` or per-model key cannot skip SSO. Third-party (BYOK) endpoints keep working, since their `base_url` is not on `x.ai`”) and `force_login_team_uuid` (team-UUID pin, single or list; “an empty list rejects every login”; “Setting this also turns on `disable_api_key_auth`”). Claude migration mapping: “`forceLoginMethod` maps to `disable_api_key_auth`, and `forceLoginOrgUUID` maps to `force_login_team_uuid`.”

## TUI

“Running `grok` with no arguments starts the interactive TUI” — a “rich, mouse-interactive, fullscreen experience.” `[ui] screen_mode` picks `fullscreen` (default) or `minimal`; Grok “intentionally runs inline under Zellij and tmux control mode (`tmux -CC`)” (force fullscreen with `[terminal] alt_screen = "always"` in `~/.grok/pager.toml`).

Key chords: `Shift+Tab` cycles “Normal / Plan / Auto when available / Always-approve”; `Ctrl+O` toggles always-approve; `Ctrl+G` tasks pane; `Ctrl+B` sends the running command to the background; `Ctrl+T` todo pane; `Ctrl+\` Agent Dashboard (`Ctrl+4` in VS Code-family terminals); `Esc Esc` opens rewind when the prompt is empty; `Ctrl+R` toggles mouse capture in scrollback when `[ui] mouse_reporting_toggle` is on; `Ctrl+Space`/`F8` voice dictation (`/voice`); `Ctrl+W` worktree dialog on the welcome screen; `Ctrl+Z` restores a wiped prompt draft. Clipboard writes go to the OS clipboard, tmux buffer, and OSC 52; `grok wrap <command...>` “runs it in a local PTY that intercepts OSC 52 and writes to your clipboard” (also `docker exec`/`kubectl exec`, experimental); `/terminal-setup` reports detection. `/status-line` values render via `[ui.status_line]` (default `disabled`).

## Modes and commands

Slash commands span session (`/new`/`/clear`, `/resume`, `/sessions`, `/fork`, `/rename`, `/share` “Share the current session via URL”), context (`/context`, `/compact`, `/rewind`, `/session-info`, `/find`, `/transcript`, `/export`, `/copy [N]`), model (`/model`/`/m`, `/effort`), permissions (`/always-approve`, `/auto`, `/plan`, `/view-plan`), extensions (`/hooks`, `/plugins`, `/marketplace`, `/skills`, `/mcps` — “all open the same extensions modal”), agent tools (`/btw`, `/loop`, `/imagine`, `/imagine-video`, `/tasks`, `/create-workflow`, `/workflow`, `/workflows`, `/deep-research`, `/queue`, `/dashboard`, `/remember`), account/UI (`/usage`, `/privacy`, `/login`, `/logout`, `/settings`/`/config`, `/theme`, `/compact-mode`, `/multiline`, `/vim-mode`, `/timestamps`, `/density`, `/terminal-setup`, `/config-agents`/`/agents`, `/personas`, `/import-claude`, `/feedback`, `/release-notes`). “A few commands appear only when their feature is available (for example `/imagine` and `/loop`).” Memory commands (`/flush`, `/memory`, `/dream`) “appear when cross-session memory is enabled.”

## Headless and ACP

`grok -p "prompt"` runs headless with `--output-format plain|json|streaming-json` (“`json`: one JSON object at the end; `streaming-json`: newline-delimited JSON events”), `--no-alt-screen` (“Run inline (no alternate screen / fullscreen TUI takeover)”), and session flags (`-s` new named session, `-r` resume, `-c` continue). “Headless sessions (via `--session-id`, `--resume`, `--continue`) are stored in `~/.grok/sessions`.” For automation: “pass `--no-auto-update` … to skip background update checks,” or persist `[cli] auto_update = false` / `GROK_DISABLE_AUTOUPDATER`. Other common flags: `-m/--model`, `--effort`, `--always-approve` (“alias `--yolo`”), `--allow`/`--deny`, `--sandbox`, `--rules`, `--system-prompt-override`, `--tools`/`--disallowed-tools`, `--max-turns`, `--no-plan`/`--no-subagents`/`--no-memory`/`--disable-web-search`, `--experimental-memory`, `--cwd`, `--ref`, `-w/--worktree`. “Claude Code flag names are accepted as aliases where they overlap: `--allowedTools`, `--disallowedTools`, `--append-system-prompt`, `--system-prompt`, and `--dangerously-skip-permissions`.”

ACP: `grok agent stdio` “Run[s] as an ACP agent over stdin/stdout” (JSON-RPC). The documented flow is `initialize` (with `clientCapabilities`) → `authenticate` (`xai.api_key` or `cached_token` method ids) → `session/new` → `session/prompt`; “`session/prompt` returns completion metadata; the assistant text itself arrives as `session/update` chunks” (`agent_message_chunk`). The example assumes “`grok` is already authenticated locally, or `XAI_API_KEY` is set.”

## Enterprise and privacy

Network: required hosts are `cli-chat-proxy.grok.com` (“Inference proxy, settings”) and `auth.x.ai`; optional hosts include `api.x.ai` (API-key path), `code.grok.com` (“Remote session sync, sharing, WebSocket relay” — blocked means “Sessions stay local-only; share links unavailable”), `assets.grok.com`, and the installer hosts. “All connections use TLS 1.2 or TLS 1.3, enforced by `rustls`… There is no option to disable TLS.” Proxies honor `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY`, with `GROK_POOL_IDLE_TIMEOUT_SECS` (90s idle pool) and guidance to set proxy idle timeouts ≥10 minutes for SSE streams (600s per-chunk idle default).

The five config layers, fail-closed `requirements.toml` pins, MDM/golden-image patterns, and the Claude `managed-settings.json` partial compatibility are under configuration. Data lifecycle: input assembled locally → TLS transport → inference (ZDR orgs “route through a dedicated service identity that skips logging”) → “Tool execution — happens locally in the user’s sandboxed environment” → response → “no prompts, code, or responses are persisted at the inference layer for ZDR organizations. Local session history is stored in `~/.grok/`.” “ZDR is enforced at the team level”; video tools under ZDR need “user-supplied output storage” (`[tools.zdr_video_output_s3]`), and `disable_zdr_incompatible_tools` makes them “return setup guidance instead of generating.”

## Grok Bot is a different product

The overview’s “Next” list points at “Grok Bot — AI teammates on a cloud computer,” but the Grok Bot documentation describes a separate product: “your proactive AI teammate” that runs on “a real computer in the cloud” shared by multiple Bots, with its own pages for computers, meetings, Teams, mobile, skills/routines, vault, and security. The Grok Bot docs do not document running Grok Build CLI sessions; treat Grok Bot as a distinct xAI agent surface, not a Build deployment mode. The org’s `grok` identity set (`grokbot`, `grok`, `grokbuild`) normalizes to this single harness, with Grok Bot and the Grok assistant app kept separate.
