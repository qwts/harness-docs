# Configuration, providers, and models

**Verified:** 2026-11-15

## `config.toml` and `tui.toml`

Kimi Code CLI “writes all long-term preferences into TOML (plain-text configuration) files under `~/.kimi-code/`: runtime settings live in `config.toml`, and terminal-UI preferences live in a companion `tui.toml`.” “The CLI reads configuration from `~/.kimi-code/config.toml`, created automatically on first run”; `KIMI_CODE_HOME` relocates the data root, and “the file name is always config.toml.” TOML keys are snake_case; dotted aliases need quoting (`[models."gpt-4.1"]`).

Top-level fields include `default_model`, `default_permission_mode` (manual / yolo / auto), `default_plan_mode`, `merge_all_available_skills`, `extra_skill_dirs`, `extra_agent_dirs`, `builtin_product_skills`, `telemetry`, `auto_session_title`, `disable_feedback_survey`, plus the `providers`, `models`, `thinking`, `loop_control`, `task`, `tools`, `image`, `workspace`, `services`, `permission`, `environments`, `hooks`, and `identity` tables. Other notable sections:

| Section | Highlights |
|---|---|
| `[thinking]` | `enabled` (default true), `effort` (low / medium / high / xhigh / max), `keep` (preserved-thinking passthrough; `clear_thinking_20251015` edit on Anthropic). `default_thinking` and `thinking.mode` are deprecated (0.21.0) |
| `[loop_control]` | `max_steps_per_turn` (unset/0 = unlimited), `max_attempts_per_step` (10), `reserved_context_size` (compaction trigger), `compaction_max_attempts` (5). `max_retries_per_step` / `max_steps_per_run` deprecated (0.32.0) |
| `[token_counting]` | `strategy`: `measured+estimated` / `measured` / `estimated` — “selects which context token count is reported externally”; internal compaction logic “always uses both provider-reported usage and estimates” |
| `[task]` | Background-task concurrency: `keep_alive_on_exit`, `kill_grace_period_ms` (5000), `bash_auto_background_on_timeout` (true), `bash_task_timeout_s` (600; 0 = none), and print-mode fields `print_background_mode` (`steer` default / `drain` / `exit`), `print_wait_ceiling_s`, `print_max_turns`. Legacy `[background]` accepts the same fields |
| `[subagent]` / `[swarm]` | `timeout_ms` default 7200000 (2 h); 0 = no timeout — “defaults to no timeout in print mode” |
| `[mcp]` | `startup_timeout_ms` (30000), `tool_timeout_ms` (60000), `default_deferred`, reconnect backoff 5000→300000 ms (workspace-level servers only) |
| `[identity]` | `name` + `slug` — “Customizes how the agent identifies itself”; fills `${product_name}`, User-Agent product token, MCP client name; “resolved once at startup” |
| `[tools]` | Global switch: `enabled` allowlist + `disabled` denylist, “intersects with each agent's own tools / disallowedTools policy”; bare `*` outside `mcp__` patterns never matches and warns |
| `[read]` | `default_max_chars` / `max_chars` (both 100000); “a call also stops at about a quarter of the maximum in estimated tokens (25,000 by default)” |
| `[image]` | `max_edge_px` (2000), `read_byte_budget` (262144 = 256 KB) |
| `[database]` | `base` (minidb read model, on), `global_search` (off by default; enables `POST /api/v1/search`), `search` worker |
| `[watch]` | Filesystem watchers that hot-reload `AGENTS.md`, skills, MCP config, and workspace files; `KIMI_CODE_WATCH` outranks `[watch].enabled`. Defaults conflict across pages: the whats-new log states “Filesystem watching for config and workspace files no longer runs by default; to hot-reload AGENTS.md, skills, or MCP config, set [watch] enabled = true or KIMI_CODE_WATCH=1,” while the env-var table still lists “`[watch]` enabled (default true)” |
| `[workspace]` | `require_trust` (default true) — “false treats every workspace as trusted and skips the startup trust prompt”; `KIMI_CODE_TRUST_WORKSPACE=1` is a separate per-process override that “does not write a persistent trust record” |
| `[environments]` | Remote environment declarations (SSH / Docker / custom launcher) with optional `default` |
| `[services]` | Exactly `moonshot_search` and `moonshot_fetch` (web tools); env `KIMI_WEB_SEARCH_*` / `KIMI_WEB_FETCH_*` take priority over config |
| `[experimental]` | `tower = true`, `tool-select = true`, `notify_user = true` flags |

`tui.toml` holds theme (`auto`/`dark`/`light`/custom), `tui_mode` (`regular`; `fullscreen` experimental), `render_latex`, `cache_expiry_hint`, `[editor].command`, `[notifications]` (`enabled`, `notification_condition` unfocused/always), `[upgrade].auto_install` (auto-update, on by default), `[transcript]` density, and `[status_line]` (`items` slots mode/goal/model/tasks/cwd/git/tips, or a `command` whose first stdout line replaces the footer — “capped at 300ms, throttled to once per second”). “Changes apply on the next start, or immediately with /reload-tui (which reloads only tui.toml); /reload reloads both config.toml and tui.toml.”

## Providers

Each `[providers.<name>]` entry defines an API provider. Supported `type` values: `kimi` (OpenAI-compatible — managed Kimi Code service or Kimi Platform API key), `anthropic`, `openai`, `openai_responses`, `google-genai`, and `vertexai`. “All providers communicate with models in streaming mode by default. Capabilities such as thinking, vision, and tool use are matched automatically by model name prefix.”

Credential handling is the defining rule: “The CLI reads credentials only from here. It does not fall back to shell environment variables automatically: running export KIMI_API_KEY in the terminal does not give any provider its key.” Resolution per provider: `api_key` or `api_key_env` — “mutually exclusive alternatives — set exactly one” — then the `[providers.<name>.env]` sub-table (e.g. `KIMI_API_KEY = "sk-xxx"`), else “startup fails with an error.” `api_key_env` is “re-read from the process's own environment on every request”; an unset or empty variable “fails fast with an error naming the provider and the variable” and “is never silently ignored, with no fallback to another credential source.” The one system-environment exception is `GOOGLE_APPLICATION_CREDENTIALS`, “read by the Google SDK directly via the standard ADC flow; the CLI does not participate.” Vertex AI requires `GOOGLE_CLOUD_PROJECT` / `GOOGLE_CLOUD_LOCATION` in the provider env sub-table — “Simply export GOOGLE_CLOUD_PROJECT in the shell will not be read by the CLI.”

The managed service uses OAuth, not static keys: “After running /login, the built-in authentication toolchain automatically writes and refreshes credentials.” OAuth endpoints can be redirected with `KIMI_CODE_OAUTH_HOST` → `KIMI_OAUTH_HOST` → `https://auth.kimi.com`; the managed base URL is `KIMI_CODE_BASE_URL` (default `https://api.kimi.com/coding/v1`) — “`KIMI_CODE_BASE_URL` (OAuth-managed service, targeting kimi.com) and `KIMI_BASE_URL` (direct API key connection, targeting moonshot.ai) are two distinct variables.” `/provider` (or `kimi provider` in the shell) manages providers interactively; third-party imports come from models.dev (“Deprecated and alpha-status models are excluded”), with a built-in snapshot fallback for offline use, and custom api.json registries can declare `upgrade` metadata (`model`, `migration_markdown`, `retirement_at`) that drives migration prompts. “Kimi Code OAuth managed accounts logged in via /login do not appear in /provider.”

## Models

Each `[models.<alias>]` entry defines an alias: required `provider`, `model`, `max_context_size`; optional `max_input_size`, `max_output_size` (“currently only the anthropic provider reads it”), `capabilities`, `support_efforts`, `default_effort`, `off_effort` (“the only way to actually stop reasoning on models that reason by default”), `upgrade`, per-model `base_url`, `display_name`, `reasoning_key` (openai), and `adaptive_thinking` (anthropic). `[models."<alias>".overrides]` survives provider-model refreshes but “does not accept identity / routing fields (provider, model, protocol, beta_api, and base_url).”

The `KIMI_MODEL_*` family “synthesizes a temporary provider in memory, and the change does not persist after restart”; “these variables take priority over default_model in config.toml, but the `-m <alias>` option at startup still has the highest priority.” Required: `KIMI_MODEL_NAME` and `KIMI_MODEL_API_KEY`; `KIMI_MODEL_MAX_CONTEXT_SIZE` defaults to 262144.

The managed catalog (provisioned by `/login`) defaults to three aliases — `kimi-code/k3` (1M context), `kimi-code/kimi-for-coding`, `kimi-code/kimi-for-coding-highspeed` (262144) — against provider `managed:kimi-code` at `https://api.kimi.com/coding/v1`. The product model page lists six model IDs: `k3.1-pro`, `k3.1-pro-highspeed` (“approximately 2–3× speed, 2× quota usage”), `k3`, `k3-256k`, `kimi-for-coding` (K2.8 Preview), and `kimi-for-coding-highspeed` (K2.7 Code Highspeed, “~5–6× faster output”). Effort routing for third-party tools maps `ultra`/`max`/`xhigh` → max, `high`/`medium` → high, `low`/`minimum`/`light` → low, and “K2.7 Code Highspeed does not support adjustable thinking effort.” Guardrails: “K3.1 Pro models only support thinking mode. Requests with thinking disabled are rejected,” while on the K3 series / K2.8 Preview / K2.7 Code Highspeed “requests with thinking disabled are served by K2.8 Preview without thinking,” and “A mistyped model ID falls back to K2.8 Preview without thinking.”

## Subagent model pool

“Subagents inherit the model the main agent is running by default. The `[secondary_model]` section makes this configurable”: a `default_model` plus a `models` pool of aliases with selection hints, and a section-wide `default_effort`. “Subagents only run on models listed in the pool”; a two-or-more-entry pool enables per-spawn selection via the `model` parameter on Agent/AgentSwarm. Resolution order: explicit tool-call model → pool `default_model`; “A value that is not a pool alias fails the spawn with an error listing the available choices.” The former `force` key: “The former force key has been removed: a lone default_model already pins every subagent to one model. A configuration that still sets force loads with a warning and the key is ignored.” `/secondary-model` (alias `/subagent-model`) writes the default from the TUI. Same-model “variant” entries let a pool expose multiple thinking efforts; note the documented asymmetry — “for the main agent, a configured global `[thinking].effort` overrides the variant's `default_effort`; for subagents the variant's `default_effort` wins over the global value.”

## Overrides, retries, and project-level config

The overrides page stresses that the three channels “are not a simple priority stack”: config file = long-term, CLI options = one-off, environment variables = locating config (`KIMI_CODE_HOME`), subsystem switches (`KIMI_DISABLE_TELEMETRY`), and endpoints/diagnostics. “Ordinary runtime parameters do not fall back to shell environment variables.” “The CLI currently reads a single user-level config file and has no project-level config file mechanism” — the exceptions are project permission rules (`.kimi-code/local.toml`, trusted workspaces only) and project `mcp.json`. CLI options: `-S/--session [id]`, `-c/--continue`, `-y/--yolo` (Ask When Needed), `--auto` (Never Ask), `--plan`, `-m/--model`, `-p/--prompt`, `--output-format <text|stream-json>`, `--skills-dir` (repeatable, replaces discovery for the launch), `--agent`, `--agent-file`, `--add-dir`; mutual exclusions fail at startup (`--continue` vs `--session`; `--prompt` with `--yolo`/`--auto`/`--plan`; etc.).

Retries are scoped: “Retries only apply to transient failures: connection errors, timeouts, HTTP 429 rate limits, and 5xx server errors. A 429 caused by an exhausted quota or insufficient account balance is not retried and fails immediately.” `KIMI_CODE_INFINITE_RETRY` enables indefinite retries with exponential backoff (32 s cap) honoring `Retry-After`.

## Data locations

Everything lives under `$KIMI_CODE_HOME` (default `~/.kimi-code`): `config.toml`, `tui.toml`, global Kimi-specific `AGENTS.md`, `mcp.json`, `skills/`, `plugins/installed.json` + `plugins/managed/`, `session_index.jsonl`, `credentials/` (“dir 0700, files 0600”, atomic tmp → fsync → rename writes), `sessions/<workDirKey>/<sessionId>/` (with `state.json`, `agents/main/wire.jsonl`, `agents/main/plans/`, subagent dirs, `tasks/`, `cron/`), managed `bin/rg` + `bin/fd` binaries, `logs/`, `updates/`, and `user-history/<md5(workDir)>.jsonl`. “Generic `.agents` resources stay under the real OS home so they can be shared across tools.” Implicit workspaces get ids `wd_<slug>_<first-12-chars-of-sha256>`; managed workspaces `wm_<uuid>`.
