# Config and steering

## The `.kiro/` root

- **✅** All Kiro surfaces read the same `.kiro/` directory at project root — config "travels with your repository". Subdirs seen in docs: `steering/`, `hooks/`, `specs/` (generated by the spec workflow), `settings/` (MCP config).
- **✅** Surface-specific behavior exists for permissions and primary-agent selection; everything else is shared.

## Steering files

Markdown files giving the agent persistent project knowledge (conventions, patterns, standards).

| Scope | Path | Surfaces |
|---|---|---|
| Workspace | `.kiro/steering/*.md` | IDE, CLI, Web, Mobile |
| Global | `~/.kiro/steering/` | IDE, CLI only (cloud sandbox can't read it) |
| Team | pushed via MDM/Group Policy into `~/.kiro/steering/` | same as global |

- **✅** On Web, "global steering" = your local `~/.kiro/steering/` uploaded via **Configuration Sync**; the cloud copy then applies to all cloud sessions.
- **✅** IDE can generate three foundation steering files from the UI.

## Inclusion modes (frontmatter)

YAML frontmatter at the very top of a steering file (must be first content):

| Mode | Behavior |
|---|---|
| `inclusion: always` | Default; loaded into every session |
| `inclusion: fileMatch` | Loaded when a matched file is in context (uses `fileMatchPattern`) |
| `inclusion: manual` | Only when explicitly invoked |
| `inclusion: auto` | Description-matched auto-activation; also surfaces as a `/name` slash command |

- **✅** CLI V3 supports all four; CLI V1/V2 auto-load only `always` — `fileMatch`/`manual` files are excluded from automatic loading there.

## AGENTS.md

- **✅** Supported as a parallel convention: repo root, **and discovered in subdirectories** throughout the workspace, plus `~/.kiro/steering/AGENTS.md` for global.
- **⚠️** AGENTS.md files are **always included** — no inclusion modes; that's the steering-file-only feature.

## Custom-agent steering

- **✅** Agent configs can attach steering via `resources: ["file://.kiro/steering/**/*.md"]`.

## Other config-adjacent files

- **Kiroignore** — keeps secrets/sensitive paths out of agent context; enforced on **IDE + CLI V3 only**, unavailable on Web/Mobile (capability listing; exact filename/format ❓).
- **Configuration Sync** — opt-in upload of local steering/config to cloud configuration for Web sessions.
- **Compaction** — built-in context management for long sessions (not user-configured).
