# Roo Code corrections log

**Verified:** 2026-11-16 (Roo Code v3.54.0 final release; docs site main — product sunset May 15, 2026)

| Claim | Verdict | Correction |
|---|---|---|
| Roo Code is an actively developed harness. | ❌ FALSE | “All Roo Code products (Extension, Cloud, and Router) will be shut down on May 15, 2026” — already past. The extension repository was archived and unused balances refunded; the docs recommend “Cline (open-source extension) or roomote.dev (our next project)” and the README points to the community fork ZooCode. This set documents the final state. |
| Roo Code is a terminal CLI. | ⚠️ PARTIAL | The primary surface was “a VS Code extension that brings AI-powered coding assistance directly to your editor,” and the other documented surface was Cloud (“Cloud Agents are an autonomous AI development team working 24/7”). But an official prerelease CLI did ship: “Roo Code CLI v0.1.17” (2026-03-04, one of 32 `cli-v0.1.x` prereleases) installs via “`curl -fsSL https://raw.githubusercontent.com/RooCodeInc/Roo-Code/main/apps/cli/install.sh | sh`” (Node.js ≥ 20; macOS Apple Silicon, Linux x64/ARM64) and runs tasks as “`roo "What is this project?"`”, with “`--create-with-session-id`” and stdin-stream create/resume task operations per its release notes. The CLI never left prerelease before the sunset. |
| Roo Code is bound to one vendor's models. | ❌ FALSE | “Other tools are intinsically bound by design to a specific provider … Roo on the other hand is **model-agnostic**.” Provider pages cover Anthropic, OpenAI, OpenRouter, Gemini, Bedrock, Vertex, DeepSeek, Mistral, Moonshot, MiniMax, xAI, Z AI, Requesty, Fireworks, Baseten, SambaNova, LiteLLM, Vercel AI Gateway, VS Code LM, Ollama, LM Studio, and OpenAI-compatible endpoints. |
| Roo Code is unrelated to Cline. | ⚠️ PARTIAL | “Cline … (from where Roo Code originated)” per the README's alternatives note; the marketplace ID is still `RooVeterinaryInc.roo-cline`. Roo Code is a long-diverged fork, not a rebrand. |
| Checkpoints are off by default. | ❌ FALSE | “**Checkpoints are enabled by default.**” They require Git (“Git must be installed for checkpoints to function”) but “No GitHub account or repository is required.” |
| Queued messages respect your approval settings. | ❌ FALSE | “When a queued message is processed, Roo implicitly approves whatever would normally require your confirmation (tool calls, file writes, running commands)—even if auto-approval is disabled.” |
| Context condensing is opt-in. | ❌ FALSE | “This feature is **enabled by default**” — the Intelligent Context Condensing page summarizes earlier dialogue when the context window nears its limit. |
| Custom tools ask before running. | ❌ FALSE | “Custom tools are **automatically approved** when enabled—Roo won't ask for permission before running them. Only enable this feature if you trust your tool code.” |
| Exported settings files are safe to share. | ❌ FALSE | “Crucially, this includes **API keys in plaintext**. Treat this file as highly sensitive.” |
| Auto-approval is purely per-permission granular. | ⚠️ PARTIAL | There is a master toggle: “Enabled (bottom-right): master pause/resume for auto-approval” plus per-permission tiles and “All / None” chips — “you can keep Enabled On with "None” selected.” The docs warn “Command line access is particularly dangerous.” |
| MCP servers are configured only per project. | ❌ FALSE | “**Global Configuration**: Stored in the `mcp_settings.json` file … **Project-level Configuration**: Defined in a `.roo/mcp.json` file … If a server name exists in both global and project configurations, the **project-level configuration takes precedence**.” |
| Orchestrator mode requires building a custom Boomerang mode first. | ❌ FALSE | “The `🪃 Orchestrator` mode (previously achieved via a custom "Boomerang Mode") is now a built-in mode specifically designed to orchestrate workflows by breaking down tasks and delegating them to other modes.” |
| Architect mode can edit any project file. | ❌ FALSE | Its tool access is “`read`, `mcp`, and restricted `edit` (markdown files only)”; only `💻 Code` and `🪲 Debug` have “Full access to all tool groups.” |
| Codebase indexing works out of the box. | ⚠️ PARTIAL | It “creates a semantic search index of your project using AI embeddings” (and elsewhere “creating a semantic search index using AI embeddings”), parsing with “Tree-sitter” and storing vectors in “a Qdrant database” — you must supply an embeddings provider and a Qdrant instance (a free tier path via Qdrant Cloud/Docker + Gemini is documented). |
| Project rules must live in a single `.roorules` file. | ⚠️ PARTIAL | The directory is the “Preferred Method: Directory (`.roo/rules/`)”; the single file is the “Fallback Method: Single File (`.roorules`)”. Same pattern per mode with `.roo/rules-{modeSlug}/` and `.roorules-{modeSlug}`. |
| Skills load their full instructions at startup. | ❌ FALSE | “**Level 1: Discovery** - Roo reads each `SKILL.md` file and parses its frontmatter … Only this metadata is stored for matching—the full content isn't held in memory until needed.” Instructions load via `read_file` on match (Level 2). |
| Everything in Roo Code Cloud is paid. | ⚠️ PARTIAL | “Connect the Extension to Cloud … Free”, “Analytics … Free”, “Task Sync … Free”, “Task Sharing … Free”; “Cloud Agents | Run Roo in the cloud with credit-based runtime and BYO provider keys | Paid”. Cloud Agents are “available in all Roo Code Cloud plans, including the free one” with credits for runtime. |
| Cloud Agents run inside your local checkout. | ❌ FALSE | “they work on isolated branches and deliver work via PRs” — Coder agents “make changes in its container environment, commit them locally, push to the remote repository and create a PR.” |
| The Roo Code Router requires provider API keys. | ❌ FALSE | “it only needs your Roo Code Cloud account … you don't need to manage API keys to use it – just connect your account.” |
| `.rooignore` changes need a reload. | ❌ FALSE | “Roo actively monitors the `.rooignore` file. Any changes you make are reloaded automatically” — and “The `.rooignore` file itself is always implicitly ignored, so Roo cannot change its own access rules.” |
| The active mode resets between sessions. | ❌ FALSE | “your selected mode persists between sessions—Roo remembers which mode you were using when you return,” and “Each mode remembers your last-used model.” |
| Checkpoints are captured before every command. | ❌ FALSE | “Checkpoints are recorded when tasks begin and before file modifications. They are not automatically created before command execution.” |
| The extension costs money. | ⚠️ PARTIAL | “**Roo Code VS Code** (the extension) is 100% free”; the Router “offers both free and paid models” and Cloud Agents are paid via credits. |
| Worktrees work in multi-root workspaces. | ❌ FALSE | Requirements include “Multi-root workspaces are not supported” and “Workspace must be at the repository root (not a subfolder).” |
| `run_slash_command` is a standard tool. | ⚠️ PARTIAL | It is marked “*(Experimental - requires enablement)*” in the tool table and “Experimental feature - requires explicit enablement in settings” in the group note, and is listed under experimental features. |
| Rate limits are a global setting. | ⚠️ PARTIAL | “Rate limits, which default to 0 (disabled) and typically don't need adjustment, are now configured per profile.” |
| Shadow-Git checkpoints touch your repository config. | ❌ FALSE | “The shadow Git repository operates independently from your project's existing Git configuration,” and “No Git personal information configuration is needed.” |
| The extension is installable only in VS Code. | ⚠️ PARTIAL | The docs cover “VS Code, Cursor, VSCodium, and other compatible editors” via Marketplace and “Open VSX Registry - for VS Code-compatible editors like VSCodium,” plus manual VSIX installation. |
| Roo Code Cloud uses managed inference only. | ❌ FALSE | Cloud Agents use “credit-based runtime and BYO provider keys” — “All of it follows our philosophy of being model-agnostic and letting you bring your provider key.” |
