# CLI surfaces, headless, and SDKs

**Verified:** 2026-11-15

## Three entry points

The three entry points are the Interactive TUI (`mcode [prompt]`), Headless (`mcode exec [prompt]`), and ACP (`mcode acp`). The three “share sessions, models, providers, plugins, and permission controls, while exposing different interaction boundaries,” and “The CLI does not depend on Electron or desktop IPC.” Install: `curl -fsSL https://filecdn.minimax.chat/public/install.sh | bash` (macOS/Linux/WSL), `irm https://filecdn.minimax.chat/public/install.ps1 | iex` (Windows PowerShell), or `npm install -g @minimax-ai/code`. Node requirements for manual install: “22.19.0 or later in the 22.x line,” or Node 24/25/26; “Alpine and other musl-based Linux distributions are not currently supported by the installer.” Current CLI line: 0.7.7 (2026-11-12 changelog); `mcode update` self-updates.

## TUI

Keys: `Enter` sends/steers, `Alt+Enter` queues a follow-up, `Shift+Enter` newline, `@` file/directory references, `Ctrl+V` image/video paste (0.4.6 adds a paste preview), `Shift+Tab` Plan Mode, `Alt+M` permission mode, `Esc` interrupt/panel close. “While a task runs, press `Enter` or use `/steer <message>` to guide the current response.” Message editing (0.4.8): “press `Esc` twice with an empty input, or use `/edit` to edit the previous message,” with images returning as editable `[Image #1]` labels. Slash commands cover sessions (`/new`, `/sessions [query]`, `/fork`, `/rewind`, `/edit`, `/retry`, `/rename`, `/compact [instructions]`, `/export [path.md]`, `/transcript`, `/copy`), runtime (`/status`, `/permission`, `/login`/`/logout`, `/doctor`, `/context`, `/model`, `/provider`), capability (`/plugins`, `/skills`, `/mcp`), input (`/steer`, `/add-dir`, `/queue`), and application (`/help`, `/settings`, `/update`, `/feedback`, `/quit`) — plus `/usage`, `/goal`, `/plan`, `/parent`, `/hotkeys` (0.7.x), and `/btw`.

Side conversations (0.3.2): `/btw [question]` (alias `/side`) opens “a temporary side conversation” — “It inherits context from the main conversation's most recent committed boundary while the main task keeps running.” “The side conversation retains the current tool permissions, but tools that can modify data always require your explicit confirmation, including in Full access mode.” `Ctrl+/` switches views, `/parent` returns, and “Temporary side conversations do not appear in `/sessions` or `/resume`.”

Goals: `/goal <objective>`, `/goal budget=50K` (“positive integers with optional `K` or `M` suffixes; use `budget=clear` to remove the cap”), `/goal pause|resume|edit|clear`. “Goal budgets accept positive integers with optional K or M suffixes.” Plan Mode: `/plan on|off|status|view` or `Shift+Tab` — “Plan Mode controls whether the agent plans before execution. Permission mode controls how tool actions are handled. They are independent settings.”

## Sessions

`mcode --continue` (latest in workspace), `mcode --session [id]` (browser when omitted); “`--session`, `--continue`, and the compatibility alias `--resume` cannot be combined.” `mcode init [directory]` “analyzes the directory structure, project rules, and available scripts, then generates or updates `AGENTS.md`” (starts the TUI for the init task).

## Headless (`mcode exec`)

One task without the TUI. Key options: `--cwd`, `--file <path>` attachments, `--model provider/model[#variant]`, `--effort <level>` (0.4.9; “Unsupported levels and models without effort support fail with a non-zero exit code before the task starts,” and “The override is not saved to the session”), `--prompt-mode tui|coding|work` (0.4.7; “selects system instructions for regular `exec`”; on resume “the selected mode must match the saved session mode”), `--session <id>` / `--continue` (not combinable), `--config <path>`, `--permission smart|full|off` (default `smart`), `--timeout <duration>` (`ms|s|m|h`), `--max-steps <count>`, `--output-format text|json|stream-json`, `--output-schema <schema>`, `-o/--output-last-message <path>`, and `--input -` (stdin only when explicit; “Do not combine `--input -` with a positional prompt”; `--input-format json` accepts `{ "prompt": "..." }`). Attachments: “A run accepts up to 10 files and 100 MB total” on the automation page — the 0.7.7 changelog raises the per-message limit to 20 in TUI/exec/ACP with the 100 MiB total unchanged (doc-vs-doc; changelog is newer).

Output contract: “Task results go to stdout and diagnostics go to stderr.” `json` prints “one stable `ExecResult` JSON document” (`schemaVersion`, `runId`, `sessionId`, `turnId`, `status`, `output`, optional `model`/`usage`, `durationMs`); `status` ∈ `succeeded|failed|timeout|cancelled|limit_exceeded`. `stream-json` prints “newline-delimited, versioned events” (`exec.started/completed`, `session.started/resumed`, `turn.started/completed/failed`, `item.started/updated/completed`) to “Process events by `sequence` and preserve forward compatibility for unknown event types.” `--output-schema` requires the final answer to match the Schema — “Parsing or validation failures return `status: failed` with error code `STRUCTURED_OUTPUT_INVALID`” — and `--output-last-message` “writes atomically only after a successful run and Runtime shutdown.” Interaction gate: “`mcode exec` fails on pending questionnaires or permission requests instead of bypassing interaction.”

Stable exit codes: 0 success, 2 invocation/input error, 3 configuration error, 4 runtime/task failure, 6 timeout, 7 runtime limit exceeded, 70 internal error, 130 cancelled, 141 broken pipe — “Check both the process exit code and the JSON `status`.” `SIGINT`/`SIGTERM`/`SIGHUP` cancel the run.

## ACP

`mcode acp` runs an Agent Client Protocol server over stdio: “stdout is reserved for protocol messages; logs and diagnostics go to stderr.” Hosts receive “Agent replies, reasoning, and tool status”, “file locations and diffs”, “permission prompts and questions”, “cancellation”, and “model and Plan controls.” Editor config is the generic custom `agent_servers` entry with `command: "mcode"`, `args: ["acp"]`. From 0.7.x, ACP permission-mode changes “apply only to the current ACP process” (previously they leaked into shared `config.yaml`).

## SDKs

TypeScript `@minimax-ai/code-sdk` (Node `>=22.19 <23` or `>=24.2 <27`) and Python `minimax-code-sdk` (Python `>=3.10`), both driving “the local CLI with `mcode exec --output-format stream-json`: one `run()` / `runStreamed()` call is one CLI process and one Turn,” with `MIN_CLI_VERSION` 0.6.3. Lookup order: `bin` option → installed `@minimax-ai/code` peer → `mcode` on `PATH`; `resolveFromCwd` defaults to `false` (“Leave it off for untrusted checkouts”). Thread options map to CLI flags (`cwd`, `model`/`effort`, `permission` smart/full/off, `mode` standard/lightweight — “only valid for a new Thread” — `promptMode`, `systemPrompt`/`appendSystemPrompt` via temporary files). Errors all extend `MCodeError` carrying `exitCode`, `signal`, and “the last 64 KiB of CLI stderr”; “The SDK never retries automatically.” Cancel sends SIGTERM with ~60 s grace then SIGKILL; `timeoutMs` force-stops at “`timeoutMs + 90s`.” “A Thread runs one Turn at a time. A concurrent call throws `ThreadBusyError`; Turns are not queued.” Not in Phase 1: `outputSchema` (structured-output constraints), plus “Approval callbacks, steering a running Turn, continuing after an interrupt, and forking.” `usage.totalTokens` excludes `cacheReadTokens` / `cacheWriteTokens`.
