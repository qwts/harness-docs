# Desktop app and automation

**Verified:** 2026-11-15

## Desktop app

“MiniMax Code is a desktop AI Agent app for software development, everyday workflows, automation, and remote collaboration,” on macOS 12 Monterey+ and Windows 10+ (global site code.minimax.io, China site code.minimax.cn; Homebrew cask `minimax-ai/tap/minimax-code` — macOS only, “Without `--language`, the Mainland China build is installed”; current desktop release v3.1.15, 2026-11-13). The app was rebranded to MiniMax Code with “a new minimax CLI shortcut added” (changelog).

Modes: Coding (“keeps project context, files, changes, terminal, and browser tools close at hand”) vs Work (“tasks where you care more about progress and deliverables”) — “Work mode hides some developer panels to reduce technical detail.” Tasks: every conversation creates a task record; the sidebar offers New Task, Search, Pinned, project-grouped history, Agent Team, Scheduled tasks, Archived. Cloud collaboration: local/cloud session list, `/` → “Continue in Cloud” handoff with a recommended-resources card — “Each handoff file and the total selected files must be no larger than 500 MB” — and “Local and cloud project files do not continuously sync. Later local edits are not uploaded automatically, and cloud changes are applied to the original workspace only after you confirm.” Panels: Files (Windows can “preview DOCX, XLSX, and PPTX files directly”), Changes, Change Graph (commit-by-commit history view with copy-SHA and add-to-context), Terminal. Built-in Browser: “Browser Use 2.0 adds multi-tab support,” mobile preview mode, visible cursor trail, and a choice of built-in vs system browser per page type. Infinite Canvas: image/video/HTML nodes with annotate-to-edit and Vary suggestions; HTML nodes can be dropped directly and “Add to chat” feeds canvas selections to the Agent. Appearance: themes (Default/Graphite/Warm), wallpaper (≥1024×576, ≤20 MB, PNG/JPEG/WebP/AVIF, auto color matching), density, conversation width, UI/code font overrides. Voice input with hold/toggle dictation shortcuts (unassigned by default). Shortcuts: command palette, global shortcut conflicts clearable in Settings → Shortcuts; v3.1.x adds a Mini Window. Feedback: up to 6 screenshots, auto-captured window, task metadata attachment, “My Feedback” ticket tracking.

## Goal (outcome-driven work)

“Goal lets you give MiniMax Code a clear destination with explicit acceptance criteria” — “As long as the goal has not been achieved, it can determine the next step without waiting for you to say “continue” after every turn.” Entry is explicit: “Typing `/goal` directly in the input box does not enter Goal mode. Select **Goal** from the `/` command menu or the `+` menu first.” “Goal stops when the outcome has been achieved, progress is blocked, or you pause it,” and “Goal is not unrestricted background automation. It remains subject to the task scope, user control, available budget, and evidence that can actually be verified.” Effective goals define “the final outcome, the evidence that proves completion, and the conditions that must remain true,” with a documented template structure for outcome/constraints/boundaries/blockers. Avoid Goal when the destination is unverifiable, one-step, subjective, or high-impact; the warning block advises usage limits (“Pause or edit the Goal if the limit is reached, there has been no progress for two consecutive attempts, or the work is moving in the wrong direction”). In the CLI, the separate `/goal <objective>` slash command with `budget=` suffixes provides the session-level loop.

## Scheduled tasks

Desktop/WebUI sidebar feature: “Set the name, instruction, Agent, timing, and conversation mode,” triggerable immediately. Constraint: “Scheduled tasks depend on the desktop runtime. If the computer is asleep or the app is not running, tasks may not run on time.” WebUI ships four templates (Daily summary, Weekly plan, Periodic project check, One-time reminder) and writes results back to their session.

## Remote Control and messaging

Remote Control pairs a phone to the running desktop app: the phone can “Check task progress”, “Send follow-up instructions”, “Approve permission requests”, and “View task outputs and selected file content.” WebUI's pairing code is “single-use, never written to disk, and never sent back to the browser,” and reconnects automatically after a service restart. Messaging integrations differ by locale — “Chinese / Mainland China” gets “WeChat, Feishu”; “English / global” gets “Telegram, WeChat, Lark” — WeChat via QR scan, Feishu/Lark via authorization flow, Telegram via bot token.

## WebUI (community)

“WebUI is a community project, developed and maintained by” Jia Xiaoyuan (@Fectivnfy112357), “open source on GitHub: [mcode-webui/minimax-code](https://github.com/mcode-webui/minimax-code)” (first-party code MIT). It is “a peer of the desktop app and the terminal client, not a web wrapper around either one. All three implement the same session protocol, so your account, session history, skills, plugins, memory, and scheduled tasks are the same.” Install `npm install --global @minimax-webui/minimax-code` then `mcode-webui`; serves `http://127.0.0.1:2233/` with a per-launch token in the URL; `WEBUI_HOST`/`WEBUI_SERVER_PORT`/`WEBUI_MINIAPP_PORT` (49152)/`WEBUI_OPEN_BROWSER` env vars; shares `~/.minimax` with the CLI. Permission switch: “Ask for approval (default)” vs “Full access.” Not supported vs desktop: device-to-cloud task handoff is “Not supported” (“Cloud sessions and handoff are desktop features”), as are “Inline comments / reply feedback”, the “Change graph”, and the Quick window — plus voice input. LAN exposure guidance: `WEBUI_HOST=0.0.0.0` prints a LAN URL carrying the per-launch token, but “Don't expose it directly to the internet.”
