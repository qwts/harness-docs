# MiniMax Code harness

**Verified:** 2026-11-15 against the official MiniMax Code documentation at agent.minimax.io/docs (MiniMax) plus the MiniMax-AI/minimax-code GitHub repository
**Status:** Reference documentation, not a runtime conformance audit
**Primary scope:** `mcode` CLI (npm `@minimax-ai/code`, Node ≥ 22.19 in 22.x or 24/25/26; TUI, `mcode exec` headless, ACP), `~/.minimax` data directory and `config.yaml`, providers and model references, permission modes, plugins and MCP, skills, desktop app (Coding/Work modes, panels, browser, Computer Use, Goal), scheduled tasks, Remote Control and messaging integrations, TypeScript/Python SDKs, community WebUI, M Plan/BYOK
**Provenance:** Official MiniMax sources unless explicitly marked otherwise (the WebUI docs page covers a community project and is labeled as such)

MiniMax Code (MiniMax) is a coding-agent product with three first-party surfaces sharing one session protocol — the terminal CLI (`mcode`), a desktop Electron app, and editors via ACP — plus a community browser client (WebUI). The CLI is the registry identity `mcode`: an interactive TUI with plan/goal/side-conversation support, a headless `mcode exec` with text/json/stream-json output, a stable exit-code table, and JSON-Schema structured output, and an ACP stdio server. Configuration lives in `~/.minimax/config.yaml` (`MINIMAX_DATA_DIR` to relocate; `MAVIS_DATA_DIR` fallback) with API keys read only from environment variables (`MCODE_PROVIDER_API_KEY` default). Permission modes are Ask / Auto / Full access (+ Off), where headless `smart` corresponds to TUI Auto and `ask` is unsupported without a human approval surface. Plugins ship as `.minimax-plugin/plugin.json` packages (Skill / MCP / App capabilities, strict no-secrets/no-lifecycle-scripts rules), MCP servers configure via `~/.minimax/mcp.json` or plugin `*.mcp.json`, and the desktop adds Work/Coding modes, developer panels, a multi-tab built-in browser, Computer Use (TUI/desktop only, exclusive controller), Goal mode, scheduled tasks, Remote Control, and messaging integrations (WeChat/Feishu/Lark/Telegram by locale). The `mcode` registry identity normalizes to this single harness.

## Top corrections

- ❌ **“Headless supports the Ask permission mode.”** “Headless does not support `ask` because it has no human approval surface; use the TUI or ACP when a person must approve an action” — it “fails on pending questionnaires or permission requests instead of bypassing interaction.”
- ❌ **“`--permission smart` equals TUI Ask.”** “`smart` corresponds to TUI Auto.”
- ❌ **“Plan Mode tightens permissions.”** “Plan Mode controls whether the agent plans before execution. Permission mode controls how tool actions are handled. They are independent settings,” and “An active plan does not change the permission policy for the execution phase.”
- ❌ **“API keys live in config.yaml.”** “Provider API keys are read from environment variables” — the default variable is `MCODE_PROVIDER_API_KEY`, the CLI “reads the key but does not print it,” and `provider list` shows “only managed-login or masked-key status.”
- ❌ **“Plugin packages can ship install scripts or OAuth tokens.”** Lifecycle scripts (`preinstall`/`install`/`postinstall`), symlinks, native binaries, and executable-bit dependencies “are not accepted,” and “Do not include OAuth credentials, access tokens, refresh tokens, client secrets, or API keys in a Plugin.”
- ❌ **“Computer Use works headless or on Linux.”** “Available only in the interactive TUI after you explicitly select the official plugin. Headless runs, ACP, scheduled tasks, and subtasks cannot control the computer,” and it “works on macOS and Windows” only — with an exclusive controller (“the other reports that the computer is busy”).
- ❌ **“The SDK retries failed turns.”** “The SDK never retries automatically, to avoid replaying writes with unknown outcomes” — and its permission policies “are not equivalent to Codex OS sandbox modes.”
- ❌ **“Goal mode is unrestricted background automation.”** “Goal is not unrestricted background automation. It remains subject to the task scope, user control, available budget, and evidence that can actually be verified.”
- ❌ **“WebUI is an official MiniMax client.”** “WebUI is a community project, developed and maintained by” Jia Xiaoyuan (@Fectivnfy112357) — a peer client implementing the same session protocol, not a desktop feature; cloud handoff and inline comments are desktop-only.
- ❌ **“Scheduled tasks run while the machine sleeps.”** “Scheduled tasks depend on the desktop runtime. If the computer is asleep or the app is not running, tasks may not run on time.”
