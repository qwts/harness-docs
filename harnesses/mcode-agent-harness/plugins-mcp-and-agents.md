# Plugins, MCP, and agents

**Verified:** 2026-11-15

## Plugin marketplaces and commands

Plugins come “from an official marketplace or a local marketplace” (the local source is the `plugins` directory under the data directory). Commands: `mcode plugin list [--available] [--json]`, `add|remove|enable|disable <plugin>[@marketplace]`, `marketplace list [--json]`, `marketplace upgrade` (“refreshes all marketplace snapshots”). “When names collide, specify `@official` or `@local`, or pass `-m, --marketplace official|local`.” Initial marketplace plugins include “paid Hundsun financial data, Qichacha, EverMe, PKUlaw, and Office apps,” later WPS and WeCom, plus “Red Skill search, so you can search popular Xiaohongshu skills and reuse common social-content workflows or templates.” The desktop marketplace shows category browsing, install status, and “import a plugin from a GitHub repository” (WebUI wording).

## Package format and manifest

A plugin package carries `.minimax-plugin/plugin.json` at the ZIP root (or a GitHub repo/subdirectory). Manifest fields: `schemaVersion`, `name` (“A lowercase machine name of up to 80 characters. It must begin with a letter and may use digits and `._-` as separators”), `version` (SemVer, “Increment it whenever any package content changes”), `displayName`, `description`, `author`, `icon` (lowercase `.png`/`.jpg`/`.jpeg`/`.webp`; “Production publishing currently accepts `icon` only”), `category` (ten fixed values from `Office` to `Other`), `exampleQueries` (0–3, ≤4,096 chars each), and capability arrays `apps` / `mcpServers` / `skills` — “Capabilities that are not used must remain as empty arrays.” Submission scope (2026-09-08 note): “The third-party form currently accepts App, MCP, and Skill capabilities,” and “The current third-party intake does not accept the `hooks` manifest field or Hook JSON files.”

Hard package rules: no “Symlinks, hard links, Git LFS pointers, Git submodules, package installation lifecycle scripts (`preinstall`, `install`, or `postinstall` in `package.json`), platform-specific native binaries, and files that depend on the executable bit”; UTF-8 without BOM; ASCII-only names; and size limits — a 64 MiB original ZIP, 2,048 ZIP entries, 1,024 regular files, 16 MiB uncompressed per file, 64 MiB total uncompressed, and path caps of “512 bytes / 128 bytes / 16 segments” (full path / segment / depth). Credential ban: “Do not include OAuth credentials, access tokens, refresh tokens, client secrets, or API keys in a Plugin” — “Capabilities that require user identity must first be integrated through App/Connector.” Publishing runs through a Feishu form → frozen source → script validation → Release MR → Marketplace pipeline; a published name “describes the package distribution result, not its current Marketplace visibility.”

## Skills

Skills are documented through the plugin system: `skills/<skill-name>/SKILL.md` referenced from the manifest, YAML frontmatter where “`name` must exactly match the Skill directory name, and `description` must not be empty,” a body with “complete instructions that the model can execute directly,” unique names per plugin, and runtime exposure “as `<plugin-name>:<skill-name>` to avoid conflicts.” The CLI's `/skills [filter]` searches available skills. (The docs' dedicated Skills page is currently a stub — the plugin guide is the only specification source.)

## MCP

Two paths: local configuration (“MCP configuration is stored locally on the current device. For manual editing, the common location is `mcp.json` under the MiniMax Code local data directory, for example `~/.minimax/mcp.json`”) and plugin distribution (`*.mcp.json` referenced from `mcpServers` in the manifest). Transports: `stdio` (`command`, `args`, `env`), `http` (`url`, `headers`), `streamable-http`, and `sse`; common fields `type`, `enabled`, `description`, `timeout` (“Connection or call timeout in milliseconds” — in plugin packages “the timeout for a single tool call”). Packaged MCP restricts transports: “`stdio`, `streamable-http`, and `sse` are supported. The `http` alias is not supported,” and “`stdio.command` may contain only the name of an interpreter or executable available on PATH; it must not contain a path.” Header values can reference env (`"Authorization": "Bearer ${COMPANY_MCP_TOKEN}"`). Tool discovery scales on demand: “When many MCP tools are configured, MiniMax Code can search for relevant tools on demand instead of loading every tool definition into context at once.” Since 0.4.5, “models that support web search use a built-in search tool without requiring a separate search MCP server. User-configured MCP servers are unaffected.” CLI checks: `mcode mcp list --human`, `mcode mcp tools <server-name>`, `mcode mcp auth status` (login/expiry for authenticated servers).

## Agents and capabilities

Agent Team “brings in specialized Agents for complex work. You describe the goal once, and MiniMax Code coordinates decomposition, execution, progress tracking, and final synthesis.” Custom Agents configure “Display name and avatar”, “Description”, “Instructions”, “Default model”, “Default workspace”, and “Messaging channel bindings”, each with “its own conversation entry.” Mini Apps are agent-built plugin-packaged apps (“A Mini App is a regular MiniMax Plugin with a miniapp.json declaration”), creatable via `/miniapp-creator`, runnable in a right-hand panel / WebUI tab. H3 Max video generation runs through the video-generation plugin with model choices H3 and H3 Max and an AI watermark toggle. Memory: desktop Settings → Personalization offers “Memory” and “Proactive Memory” switches plus an editable “Memory summary”; per-conversation `/memory` separates “Use memory” (must be set before the conversation starts; “it cannot be changed afterward”) from “Generate memory” (changeable). “Turning memory off does not delete saved memories.”
