# ZCode corrections log

**Verified:** 2026-11-16 (ZCode docs zcode.z.ai/en/docs, desktop app v3.18.2 / changelog 2026-11-13; docs title: “ZCode | GLM-5.3 官方 Harness”)

| Claim | Verdict | Correction |
|---|---|---|
| ZCode is a GLM chat wrapper around a terminal. | ⚠️ PARTIAL | “ZCode is a new Agentic Development Environment (ADE)” — “ZCode puts AI Agents at the center of the workflow”: a first-party ZCode Agent with workspace/task management, terminal, Git commit, live browser preview, automations, and remote surfaces. The desktop app itself is “completely free”; you bring a model plan or key. |
| ZCode picks up the GLM environment variables already in my terminal. | ❌ FALSE | “Terminal environment variables and the ZCode desktop model setup are separate entry points, so configuration is not synced automatically.” Same for proxies: with a blank HTTP-proxy field “ZCode connects directly and does not read HTTP_PROXY or similar environment variables. That's the opposite of how many command-line tools behave.” |
| ZCode has a CLI or headless mode. | ❌ FALSE | The docs document only the desktop app (dmg/Windows/Linux installers; v3.18.2). Scheduled and idle-time tasks “run on your machine, so nothing triggers while it's asleep or the app is closed”; Remote Control and Bot Channel are control surfaces of a running desktop window — “it doesn't sync code and never creates a runtime of its own.” No CLI, API, webhook, or server-side trigger is documented (verified absence). |
| Project-level hooks are executed. | ❌ FALSE | “Project-level hooks are not executed in the current version … any hooks configuration in `<workspace>/.zcode/config.json` or `<workspace>/zcode.json` is ignored as a whole — regardless of hooks.enabled — and logged as `config_project_hooks_ignored`.” Hooks are user-level (`~/.zcode/cli/config.json`) or plugin-distributed. |
| ZCode continuously reads CLAUDE.md. | ❌ FALSE | “CLAUDE.md is not continuously read by ZCode Agent at runtime. For existing Claude Code projects, ZCode only uses it during onboarding as a one-time migration source: existing content can be copied into `AGENTS.md`, and future runs use `AGENTS.md`.” |
| ZCode merges AGENTS.md files across directory levels. | ❌ FALSE | “ZCode only reads the user global AGENTS.md and the current Workspace AGENTS.md. It does not merge multiple AGENTS.md files across directory levels. It also does not scan child directories, expand @import / @include, or choose rule files automatically by task type.” |
| Scheduled automations run in the cloud. | ❌ FALSE | “Your computer must be awake. Scheduled tasks run on your machine, so nothing triggers while it's asleep or the app is closed, and a missed one-time run is recorded as skipped rather than replayed.” A Keep awake switch exists on the Automations page. |
| Project Memory is on by default. | ❌ FALSE | “Memory is off by default and requires ZCode v3.6.4 or later”; “The switch is off by default, so you have to enable it yourself.” It also “applies to new sessions,” not in-flight conversations. |
| Over-long skill descriptions get truncated. | ❌ FALSE | “`description` is capped at 1024 characters. Going over drops the whole skill” (the diagnostic reads “description exceeds 1024 chars”), “rather than truncating it” — put long instructions in the body instead. |
| The Anthropic endpoint can bill prepaid balance / resource packages. | ❌ FALSE | “The Anthropic endpoint draws from balance only for accounts that have never purchased a Coding Plan and have received additional allowlisting; once an account has purchased a plan — whether used up or expired — it no longer bills against balance. Use the OpenAI general endpoint above instead.” |
| Idle-time tasks consume subscription quota. | ❌ FALSE | “The run is free and doesn't consume your subscription plan quota.” But they require an active Coding Plan: “Start Plan and plain API key mode are not supported,” team plans are “still rolling out,” and each idle-time task “has no schedule, runs once.” |
| ZCode opens OAuth popups on its own. | ❌ FALSE | For remote MCP services needing OAuth, “an Open authorization button appears on that server's row … Clicking it opens the authorization page in your system browser … ZCode never opens a browser window on its own.” |
| Auto-compaction has a user-configurable threshold. | ❌ FALSE | “There is currently no user-facing switch or threshold for automatic compaction.” It triggers below the nominal window by design: the system “reserves room for model output plus a safety buffer (about 34K tokens combined), so … a 128K window compacts around 94K tokens, a 1M window around 966K.” |
| You can review or clear what Memory has stored. | ❌ FALSE | “You can't browse or clear memories yet. Turning the switch off stops ZCode using them, but there's no way to review what's been remembered from inside the app.” Per-conversation “forget what I said about …” is the only removal path. |
| Subagents share the project memory. | ❌ FALSE | “Project memory applies to the main conversation only — subagents neither read nor write it.” |
| The data migration wizard imports from any agent. | ⚠️ PARTIAL | “it currently only imports conversations from Claude Code and ZCode Agent in legacy ZCode — other tools are not supported.” |
| The BigModel/Z.ai trial quota is an ongoing daily allowance. | ❌ FALSE | “the trial lasts 5 days only. The daily quota is granted during these 5 days and expires afterwards — it is not an ongoing daily allowance” (8M tokens/day, split GLM-5.3 3M + GLM-5.3-Flash 5M). |
| Thought levels transfer identically to third-party endpoints. | ⚠️ PARTIAL | “a third-party deployment of the same model may accept different levels than the official endpoint … some third-party deployments only accept up to `xhigh`, so the top level returns a 400 parameter error there.” ZCode maps levels per API (reasoning_effort vs thinking/effort). |
| Custom request parameters can be added for third-party models. | ❌ FALSE | “in `~/.zcode/v2/config.json`, a provider's options only recognizes connection settings such as `apiKey`, `baseURL`, `apiKeyRequired`, and `headers`; any other keys added by hand (e.g. `reasoning_effort`, `vl_high_resolution_images`) are silently ignored and never written into the request body.” |
| The context window of Coding Plan models is editable. | ❌ FALSE | “Coding Plan / Start Plan built-in models: the context window is issued by the server. Local edits are restored to the official value on the next sync — that's by design, not lost configuration.” Custom-provider models are editable; names ending in `[1m]` are fixed at 1M. |
| New models show their real context size automatically. | ❌ FALSE | “A newly added model, or one without window metadata, defaults to 200,000. That's why a million-token model can still show a 200K capacity after you connect it.” A `[1m]` ID suffix is recognized as 1M automatically. |
| Editing a sent message rewrites history anywhere in the task. | ⚠️ PARTIAL | “only the user message of the last turn can be edited, and editing is unavailable while the task is running or has queued messages.” |
| Forking rolls back files on disk. | ❌ FALSE | “Forking only affects conversation history — it does not roll back files on disk. Both sessions operate on the same workspace.” |
| You can fork from an interrupted reply. | ❌ FALSE | “You can only fork from a cleanly completed assistant message. Interrupted or failed partial replies have no fork entry, and neither do user messages or tool results.” Forking “isn't available while a compaction is running,” and queued messages/background tasks aren't copied. |
| Side conversations are just forks with another name. | ⚠️ PARTIAL | A side conversation is “a separate tab in the right-hand panel that runs alongside the main conversation” — desktop-only, one per task per window, inherits the main session's history as context, but “it can't be recovered” once closed, and “Goal mode, editing a sent message, forking” are not available in it. |
| The Repo wiki is product documentation. | ⚠️ PARTIAL | “It's an architecture guide to the codebase, not a product documentation site or a user manual,” favoring “project identity, main execution paths, core modules and submodules … and risk areas,” every claim carrying a source location. |
| Feishu/WeChat bots run a separate ZCode runtime. | ❌ FALSE | Bot Channel “connects external chat tools to ZCode” on your desktop; as with phone Remote Control, “Every instruction you send is carried out by whichever machine that workspace was already connected to on the desktop,” and only one phone page can be connected at a time. |
| DingTalk, Discord, and WeCom bots are supported. | ⚠️ PARTIAL | “DingTalk, Discord, and WeCom support will be completed in later versions” — today the available channels are WeChat and Feishu. |
| Custom subagents are generally available. | ⚠️ PARTIAL | “Beta — User-level custom subagents are rolling out. The capability and its scope may still change.” Built-ins are `general-purpose` (all tools) and read-only `Explore`; built-in roles “cannot be edited or deleted.” |
| Remote Development can target native Windows hosts. | ❌ FALSE | “The target needs a POSIX shell. Connecting to a native Windows remote host isn't supported. If you want the Linux environment on your own Windows machine, choose WSL.” SSH, WSL, and Docker local containers are the supported targets. |
| Idle-time tasks are generally available. | ⚠️ PARTIAL | “Idle-time tasks are being released to subscribers in batches, so the entry points may not be visible in your client yet.” |
| Browser automation needs a setup flow. | ⚠️ PARTIAL | It “comes from the official Browser Use plugin and is on by default”; if disabled, re-enable under Settings → Browser, and “The switch applies to new sessions.” The browser panel is “desktop-only.” |
| Compaction waits until the context window is full. | ❌ FALSE | “Compaction doesn't wait for the window to fill up — it reserves output space and a safety buffer in advance.” The per-item context meter is “a local estimate with a different basis than the total at the top — the two don't add up exactly.” |
