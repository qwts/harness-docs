# Surfaces: CLI, IDE, and CI/CD

**Verified:** 2026-11-15

## Install and authentication

```bash
curl -fsSL https://junie.jetbrains.com/install.sh | bash
powershell -NoProfile -Command "iex (irm 'https://junie.jetbrains.com/install.ps1')"
```

“Junie CLI is available on Linux, macOS, and Windows.” The managed launcher (the `junie` shim) owns updates and channels (`--channel=release|eap|nightly|experimental`, `--use-version=<build>`, `junie update`, `/restart` requires it). EAP builds install via `install-eap.sh` / `install-eap.ps1`; switching back means removing `~/.local/bin/junie` and reinstalling stable.

Authentication options on the welcome screen / `/account`: **Continue with JetBrains account** (subscription), **Use a Junie API key** (usage-based billing; generate at junie.jetbrains.com/cli), **Use your own API key** (BYOK), **Use custom models and endpoints** (LiteLLM, Ollama, LM Studio, custom profiles). “Depending on your JetBrains subscription and setup, the welcome screen may offer additional options, such as signing in with JetBrains Enterprise or using local models.”

## Interactive TUI

Prompts accept `@` file/folder attachments (image drag-and-drop included), `!` shell escapes, `/` command menu, real-time follow-ups “appended to the initial prompt and taken into account by the agent immediately,” Ctrl+R prompt-history search, Shift+Enter newline, and session modes: `/agent-mode` picks Classic or Chat — “The mode is locked after the first prompt of a session.” `/stats` (aliases `/usage`, `/cost`, `/quota`, `/balance`, `/credits`) shows token/cost/model breakdowns; `/context` inspects “context usage for the last measured main-agent request… This is not accumulated usage or a prediction of the next request.” `/compress` (alias `/compact`) compresses context “before the next task, which may discard some information.” `/goal [message]` runs “orchestrated, step-by-step mode” (not available with Junie Lite); `/project-onboarding` analyzes the repo for agent-effectiveness suggestions; `/demo` (see below); `/voice` records microphone input; `/update` + `/restart` apply updates.

## Headless mode

```bash
junie --auth="$JUNIE_API_KEY" "Review and fix any code quality issues in the latest commit"
junie --auth="$JUNIE_API_KEY" --review
```

The headless page carries the banner “Junie CLI is currently in an Early Access Program (EAP).” Task input: positional argument or `--task`/`JUNIE_TASK`; `--prompt` instead opens an interactive TUI that auto-submits. Output: `--output-format text|json|json-stream`, `--input-format text|json` for piped input, `--json-output-file`. Other headless-relevant flags: `--max-steps`, `--act-as-interactive` (“Run the task with the interactive prompt and tools… while still running unattended: the agent never asks the user anything”), `--system-prompt`, `--skip-update-check`, `--share-anonymous-statistics`. JSON review input drives the code-review agent: `{"codeReviewTask":{"description":"…","reviewTarget":{"type":"remoteRequest","number":42},"diffCommand":"git diff …","allowApprove":true}}` — “A diffCommand must be a plain git diff over revisions, otherwise the review fails,” and `allowApprove: false` is “set it to false to keep the agent’s approval verdict while preventing an approval from being issued on the remote pull/merge request.”

Headless project trust: “Non-interactive runs — one-shot prompts, piped-input tasks, ACP, and Gateway — cannot ask for a trust decision, so they are trusted by design and load the project’s Junie configuration (MCP servers, hooks, agents, skills, and guidelines) without prompting. Only run Junie non-interactively in projects you trust.”

## Junie GitHub Action

`JetBrains/junie-github-action@v1` “executes entirely on your GitHub runners, so your code always stays on your infrastructure.” The basic workflow triggers on `issue_comment`, `pull_request_review_comment`, `issues` (opened/assigned), and `pull_request_review` (submitted) — filtered on `@junie-agent` mentions (title, body, or comments) — with `contents: write`, `pull-requests: write`, `issues: write`. Setup requires “the Allow GitHub Actions to create and approve pull requests checkbox enabled in the Workflow permissions section of your repository’s Settings → Actions → General” — “With this setting disabled, the Junie GitHub action will not be able to create PRs, even with the pull-requests: write permission in the workflow.”

Parameters: `trigger_phrase` (@junie-agent), `assignee_trigger`, `label_trigger` (default `junie`), `base_branch`, `create_new_branch_for_pr` (default false — push to the PR’s existing branch), `prompt` (custom instructions, or the built-in `code-review` prompt), `model`, `junie_version`, `junie_work_dir` (/tmp/junie-work), `junie_guidelines_filename` (default AGENTS.md), `allowed_mcp_servers`, `resolve_conflicts`, `silent_mode` (“without repository modifications… or user-facing feedback”), `use_single_comment`, `use_structured_prompt` (default true). Auth: `junie_api_key` **or** one BYOK key (`openai_api_key`, `anthropic_api_key`, `grok_api_key`, `openrouter_api_key`, `google_api_key`) — “Provide either junie_api_key or one of the BYOK keys — not both. All API keys are automatically masked in workflow logs.” Outputs: `branch_name`, `should_skip`, `commit_sha`, `pr_url`, `junie_title`, `junie_summary`, `github_token`.

Pre-configured MCP servers: `mcp_github_checks_server` (“Analyzes failed GitHub Actions checks”) and `mcp_github_inline_comment_server` (“enabled automatically for pull_request events”). Cookbook workflows: **basic** (@junie-agent → PR), **automated code reviews** (on `pull_request` opened/synchronize/reopened; the built-in review prompt forbids modifications — “Do NOT run tests, build, or make any modifications… Comment ONLY on lines added in this diff (`+` lines)”; comment budget “For small changes, max 3 comments; medium 6–8; large 8–12”; `@junie-agent code-review` comments can trigger it without the dedicated workflow), **fix CI failures** (`workflow_run` on failure + `mcp_github_checks_server`; needs `checks: read` and `actions: read`), **audit secrets** (`silent_mode: true`; “fails the CI build if sensitive data in commits are found” — no comments, no changes), **resolve merge conflicts** (`resolve_conflicts: true` on base-branch pushes; “Always set to false for workflows with manual @junie-agent resolution”).

## Junie GitLab CI/CD

“Works with any GitLab instance.” Setup creates “a separate container project for Junie’s CI/CD pipelines (one per GitLab instance)”; env vars `JUNIE_API_KEY` (or a BYOK `JUNIE_OPENAI_API_KEY` etc.) and `GITLAB_TOKEN_FOR_JUNIE` (personal/group access token, or a service account on GitLab 19+; token needs webhook creation, project access tokens, and pipeline-trigger-token management; Owner for automatic pipeline deletion). The `.gitlab-ci.yml` uses `registry.jetbrains.team/p/matterhorn/public/junie-gitlab-wrapper` with `junie-init` (manual, `PROJECTS_TO_INIT` list of project IDs), `junie-run` (triggered by `#junie` comments or the project bot mention; MR-open events run `JUNIE_CUSTOM_PROMPT: "code-review"` automatically), and `junie-cleanup`. A committed `PROJECTS_TO_INIT` pipeline run wires webhooks and access tokens into the target projects. “Junie will perform a code review with a pre-defined prompt for any opened merge request automatically”; “To disable automated code reviews, uncheck the Merge request events checkbox in the Junie webhook’s settings.” Multiple tasks can run simultaneously “excluding parallel runs on the same MR branch.”

## Jira and YouTrack

**Jira:** Jira automation rules POST to the GitHub Actions `workflow_dispatch` API (`junie-jira.yml`) on issue creation/update, a label, or an `@junie` comment; secrets `JIRA_EMAIL`/`JIRA_API_TOKEN`/`JIRA_BASE_URL` plus `JUNIE_API_KEY`. “Junie receives the issue details (summary, description, user discussion in the comments, attached screenshots/other files), implements the changes…, and creates a GitHub PR,” updating its Jira comment with the result.

**YouTrack:** the Junie app for YouTrack adds a **Run Junie** widget and a configurable trigger name (default `@junie`); dispatches `junie-youtrack.yml` with issue data; “If a trigger comment is provided… Junie treats the comment text as the primary instruction, with the issue details used only as context.” Secrets: `YOUTRACK_TOKEN` + `JUNIE_API_KEY`.

## JetBrains IDE integration (CLI side)

“Junie CLI can connect to the Junie plugin running inside a JetBrains IDE for the same project.” Supported IDEs: Android Studio, CLion, GoLand, IntelliJ IDEA, PhpStorm, PyCharm, Rider, RubyMine, RustRover, WebStorm. The integration “is passive from the CLI side”: the plugin is discovered automatically, the CLI “selects the best matching JetBrains IDE for the current working directory,” and connects “only when IDE-backed features are needed or when you inspect the state with /ide.” Benefits: symbol-aware code search, structure-aware edits and inspections, IDE test workflows, product-specific actions, and richer `@` completions (“classes and symbols known to the connected JetBrains IDE”) plus IDE context like open files. `/ide` lists running IDEs (Connected / Connecting… / Auth required / Error / Ready / Missing / Not responding / Unsupported — “Unsupported” fixed by “version 2026.1 or newer”). “Junie CLI currently supports only JetBrains IDEs for this integration. It does not connect to non-JetBrains editors or IDEs” — other editors use ACP.

## Junie IDE plugin

“The recommended way to use Junie is from the single AI Chat in your JetBrains IDE: select Junie by JetBrains from the list of supported coding agents and have it downloaded automatically.” The separate Junie plugin (Marketplace or from-disk install; IDE-version-gated from 2024.3.2 to 2025.2.1 depending on product) is “required only if you want to use Junie from a separate tool window.” Agent modes in the IDE: **Code** (multistep plan, autonomous execution, review/revert at the end via the Done panel) and **Ask** (read-only); a mode picker offers **Auto**. Brave Mode exists in the IDE but “is not recommended.” The IDE Action Allowlist (Settings | Tools | Junie | Action Allowlist) has IDE-specific rule types — Terminal (Java-regex style rules with `\Q…\E` literal quoting and `[^\s;&|<>@$]+` argument guards), RunTest/Build/Preview (IDE-backed, JVM in IntelliJ IDEA / C# in Rider / Android+Compose), MCP, Read/Write outside project, Edit build scripts, Edit configuration or hidden files, Read files with secrets — and “ls, cd, and pwd terminal commands with any arguments are executed without user confirmation by default. However, combining commands like `cd .. && ls` will require confirmation.” “At the moment, adding an item of the MCP Rule type … will authorize Junie to run all MCP tools without user confirmation. Defining the specific MCP servers and tools … is not possible yet.”

`.aiignore` (project root, .gitignore syntax) makes Junie “ask for explicit approval before viewing or editing” listed files — “Only the contents of files listed in .aiignore are protected. Junie will still have access to the file and folder names,” and Brave Mode or allowlisted commands can still reach them. Project Settings: Project path (the allowed-write root), Guidelines path (AGENTS.md / legacy guidelines.md; “Always specify Guidelines path for monorepos”), Enabled Technologies, “Frequency of questions from Junie” (A normal amount / Never ask), and semantic indexing. The plugin’s Models page: “Using your own API key with Junie is not supported via Junie plugin, however, you can do so in AI Assistant’s AI chat in your JetBrains IDE.”

## ACP and remote

`junie --acp true` serves Agent Client Protocol clients (“Agents that implement ACP can work with any ACP-compatible editor”), local agents over “JSON-RPC over stdio.” ACP command surface is narrower: V2 clients get `/plan`, `/skills`, `/commands`, `/import`, `/review`, `/title`, `/teleport`, `/continue`, `/feedback`, `/compress`, enabled skills, and available `/stats`/`/context`/`/logs`; “ACP V2 does not advertise TUI commands such as /ide and /remote.” `/mcp` is read-only; `/sandbox on|off` works in ACP; `/local` is advertised “only on supported macOS hardware and to ACP clients that support form elicitation.” ACP sessions are trusted (no trust prompt).

`/remote` opens “a secure tunnel to the Junie web app” (`https://junie.jetbrains.com/remote/<session-id>`) — the CLI keeps running locally and the web UI mirrors it (prompts, approvals, plan refinements, brave toggle, cancel, continue past the step limit). Requirements: JetBrains Account or `JUNIE_API_KEY` (“Bring Your Own Key (BYOK) on its own is not enough”); unavailable “when Junie CLI is signed in through JetBrains AI Enterprise”; “Your machine must stay awake while a remote session is active.” One web client at a time (“Opening the URL from another tab or device takes over the connection”); slash commands, `!` shell, `@` picks, drag-and-drop, and Ctrl+R/Ctrl+O remain terminal-only.

## Demo agent

`/demo` “asks Junie CLI to build and launch your app in a disposable VM, then interact with its UI to demonstrate a feature or change,” producing “a Markdown answer, screenshots, a screen recording, and an HTML report.” Prerequisites: “Docker running on your machine… the demo VM is a Docker container,” and “Access to a model with Computer Use support” (GPT-5.6 SOL, GPT-6 Astra, GPT-5.5, GPT-5.4 — “Otherwise, it picks the first available model in that order, preferring GPT-5.6 SOL”). VMs layer on `registry.jetbrains.team/p/junie-cli/containers/demo-base:2` (Debian bookworm with Chromium, Node, xterm, ffmpeg, xdotool, Xvfb desktop), defined at `.junie/vms/<name>/Dockerfile`, with optional `mounts` files and a `.junie/demo.md` (`vm:` + build/launch instructions; project root auto-mounts at `/workspace`). Scopes: changes of this branch, changes from this session, uncommitted changes, last commit, or a smoke test; for git scopes “the diff is the specification of the demo.”

## EAP, updates, and cache

“The Early Access Program (EAP) gives you access to pre-release versions of Junie CLI with the latest features and improvements before they are generally available” — free to join with a monthly quota; EAP-flagged features include sandbox mode, hooks, the subagents setting, and custom proxies, and the headless page marks Junie CLI itself EAP. Cache management is documented in the configuration deep-dive; `junie update` downloads the next version (“applied the next time Junie CLI starts”).
