# Mirror corrections log

**Verified:** 2026-11-15

| Claim | Verdict | Correction |
|---|---|---|
| Mirror is the name of Reflection's model. | ❌ FALSE | The model is `Beam-1.0-501B-A23B`; Mirror is the agent — “Mirror uses Reflection and `Beam-1.0-501B-A23B` unless you choose otherwise.” Beam's API record lists a 1,048,576-token context, 131,072 max output, and mandatory reasoning. |
| Mirror runs on native Windows. | ❌ FALSE | “Mirror CLI runs on macOS 14 or later on Apple Silicon, and on Linux with glibc 2.28 or later on x86-64 or ARM64,” and “Native Windows isn't supported.” |
| Mirror requires Git to start. | ⚠️ PARTIAL | “Git or Jujutsu is needed for worktree management; you can start a session in a plain directory without either.” |
| Manual approval mode sandboxes the agent. | ❌ FALSE | “Approval mode decides what you review. It isn't a sandbox. Approved commands, extensions, and local MCP servers run with your account's full permissions”; the repo README repeats “Manual approval is not a sandbox.” |
| Mirror asks before reading any file. | ❌ FALSE | Manual mode pauses for “shell commands (including ones that only read, such as `ls`), file writes and edits, connected-service tools, and most tools that extensions add,” while “Reading and searching files with the agent's built-in tools never needs approval.” |
| Auto approval mode approves everything. | ❌ FALSE | “Switch to **auto** mode to let the agent use tools without routine approval prompts. Tools that require explicit confirmation still ask, and external extensions need consent before loading.” |
| `--approval-mode` is a per-launch override only. | ❌ FALSE | It is remembered: “Use automatic or manual tool approval, and remember the choice. Defaults to `approve`, which is manual.” An explicit `--approval-mode` overrides the launch workspace's saved mode; otherwise each workspace keeps its own. |
| Mirror prompts before every tool call in a fresh directory. | ⚠️ PARTIAL | The per-directory gate is a trust question, not per-call approval: “In each new directory, it then asks `Continue and trust this folder? [y/N]`.” |
| Mirror is closed-source. | ❌ FALSE | The repo is reflection-oss/mirror under “Apache-2.0” — “Preserve the component notices and third-party licenses when redistributing source or binaries.” |
| MCP servers can be configured per project (like `.mcp.json`). | ❌ FALSE | “Mirror only reads server definitions from this directory, never from a project, so cloning a repository can't add servers” — the directory is `~/.mirror/mcp/` (relocate with `MIRROR_MCP_DIR`). Project-level `.mirror/extensions/` do exist but “Mirror asks first.” |
| MCP server definitions can embed API keys. | ❌ FALSE | For bearer auth, `tokenEnvVar` names the environment variable — “The key itself never goes in the file”; for local servers, each `env` value “is the name of one of your environment variables, not the secret itself.” |
| Authenticated MCP servers may use plain HTTP. | ❌ FALSE | “A server that uses authentication must use HTTPS. The exception is a server on your own machine (`localhost`, `127.0.0.1`, or `::1`).” |
| `/disconnect` just forgets the service, keeping its config. | ❌ FALSE | “This deletes its definition file in `~/.mirror/mcp/` and its saved sign-in,” and the reference warns “`/disconnect` deletes the server's JSON file.” |
| Web search works without any API key. | ❌ FALSE | “Web search and page reading are available when the selected provider's key is set. Mirror doesn't fall back to another provider if a call fails.” Exporting a key alone doesn't select the provider — choose with `/web-provider`. |
| The default web-search provider is chosen by which key is exported. | ❌ FALSE | “Mirror uses You.com for web search and page reading by default”; the saved `web_provider` in `config.json` decides, and You.com is the default “Without a saved choice.” |
| Mirror keeps agents running in the background after you quit. | ❌ FALSE | “Quitting Mirror stops every agent. Nothing keeps running in the background after you exit.” Sandbox VMs also stop (“Quitting Mirror stops the VMs; reopening it restarts them”). |
| Mirror supports scheduled or wake-up tasks. | ❌ FALSE | No scheduler exists in the documentation; the closest surfaces are remote agent gateways (“Remote gateways are disabled unless configured”) and queued messages that wait for the agent's current turn. |
| `/rewind` restores the files to the earlier point. | ❌ FALSE | “Rewinding changes only the conversation. Files the agent edited after that point stay as they are. Use version control to undo file changes,” and the CLI reference notes “Files aren't restored.” |
| `/drop` confirms before deleting a workspace. | ❌ FALSE | “`/drop` deletes the checkout, including uncommitted changes, without asking first. Commit or copy anything you want to keep before you run it.” The `mirror/<name>` branch and saved conversations remain; the main checkout and your only workspace can't be dropped. |
| `/fork` restores files from an earlier message. | ❌ FALSE | “A fork captures the files as they are now; it doesn't restore files from an earlier message,” and forking “requires an idle local workspace” — hosted and sandbox workspaces “can't be forked.” |
| `/worktree` copies your current edits into the new workspace. | ❌ FALSE | “Local edits and untracked files aren't copied. A checkout based on the remote's default branch also excludes your unpushed commits.” The new workspace “starts a fresh conversation,” copying only model, reasoning effort, and approval mode. |
| Renaming a workspace renames its branch and directory. | ❌ FALSE | `/rename` changes only “the name shown in the tabs and the workspace list”; “The branch, directory, and conversation keep their names.” |
| `CLAUDE.md` takes precedence over `AGENTS.md`. | ❌ FALSE | “Mirror also reads `CLAUDE.md`, so a project that already has one works without changes. If a directory has both, Mirror uses `AGENTS.md`.” |
| Mirror loads unlimited `AGENTS.md` content. | ❌ FALSE | “Mirror reads at most 32 KiB of instructions in total and truncates the rest.” |
| Project skills live in `.mirror/skills/`. | ❌ FALSE | Global skills are `~/.mirror/skills/<skill>/SKILL.md`; project skills live in `.agents/skills/` or `.claude/skills/` “in directories from the repository root down to the working directory,” six levels deep, nearest name winning. |
| Skills load into context automatically like instructions. | ❌ FALSE | “The agent sees each skill's name and description, and reads the full instructions when a task matches the description. Unlike instructions, skills cost almost nothing until they're used.” A skill without a `description` is skipped. |
| Memory is on by default. | ❌ FALSE | “Memory is off until you turn it on, and it stays on your machine” — enabled in `/settings` → Memory, stored in `~/.mirror/memory` with always-seen bullets in `~/.mirror/PINNED_MEMORIES.md`. |
| Memory syncs to Reflection's servers. | ❌ FALSE | “It stays on your machine”; `/memory import` imports “the memories that Claude Code and Codex keep on this machine,” and the setting is “unavailable in remote sessions.” |
| Mirror supports Claude-style hooks files. | ❌ FALSE | No hooks system exists in the documentation; the customization surfaces are `AGENTS.md`, skills, and Python extensions. (Extension tool-level control exists via `needs_approval` on `ToolDefinition`.) |
| Extensions are enabled automatically once discovered. | ❌ FALSE | “Before importing new external extensions, Mirror shows their source paths in an approval list” — and “external extensions also need consent before their code is imported, including in automatic approval mode.” |
| Approval mode covers extension code. | ❌ FALSE | “An extension is Python code that runs inside Mirror with your account's permissions. Approval mode doesn't restrict it. A repository you clone can include extensions in `.mirror/extensions/`, which is why Mirror asks first.” |
| `/extensions-update` also updates local-directory extensions. | ❌ FALSE | “`/extensions-update` only updates GitHub sources,” and updates are explicit — “Mirror doesn't replace a running extension just because its remote repository changed.” |
| Extension tools are exempt from approval. | ⚠️ PARTIAL | Only if the author opts out: `needs_approval=False` “lets the tool run without asking in manual approval mode. Leave the default, `True`, for any tool that changes something.” Manual mode otherwise pauses for “most tools that extensions add.” |
| Reasoning effort starts low for responsiveness. | ❌ FALSE | “Mirror starts at `max` unless the workspace has a saved effort or you pass `--reasoning-effort`.” `none` (“Provider default”) “sends no effort setting at all.” |
| `--model` and `--api` change the saved selection. | ❌ FALSE | “`--model` and `--api` apply to one launch only, while `/model` changes the saved selection.” `--approval-mode` is the opposite: “and remember the choice.” |
| Setting `OPENROUTER_BASE_URL` is harmless when using Reflection. | ❌ FALSE | “If `OPENROUTER_BASE_URL` is set and you don't pass `--api`, Mirror uses Chat Completions with that endpoint instead of Reflection. Unset it, or pass `--api reflection`, to use Reflection.” |
| The `reflection` provider accepts a custom base URL. | ❌ FALSE | “The `reflection` provider always uses Reflection's endpoint and doesn't accept another base URL.” |
| Exporting a provider API key selects that provider. | ❌ FALSE | “Each needs its own API key, read from an environment variable. Exporting a key doesn't select the provider; choose it with `/model` or `--api`.” |
| `--api-key` is the recommended way to pass credentials. | ❌ FALSE | “You can pass a key with `--api-key` instead of an environment variable, but it then appears in your shell history,” and `mirror exec` “rejects `--api-key`” outright. |
| `mirror exec` can resume a session and loads extensions. | ❌ FALSE | “`exec` starts a fresh session without extensions and doesn't support `--continue` or `--conversation-id`,” and it “rejects `--api-key`”; it also requires the directory's notices to have been accepted interactively first. |
| Calls needing approval are skipped in `mirror exec`. | ❌ FALSE | “Calls that require approval fail, so select `--approval-mode auto` only when you want automatic tool approval.” |
| `mirror acp` loads extensions for connected clients. | ❌ FALSE | ACP “starts fresh sessions without extensions” and requires accepted notices, like `exec`. |
| Remote agent gateways are available by default. | ❌ FALSE | `--remote-endpoint`/`MIRROR_REMOTE_ENDPOINT` “Configure an agent gateway supplied by your service operator. Remote gateways are disabled unless configured.” |
| Mirror is usable immediately in headless mode after install. | ⚠️ PARTIAL | For both surfaces Mirror “requires the directory's notices to have been accepted interactively” — “First open Mirror interactively in that directory to accept the usage and folder notices.” |
| Sandbox workspaces isolate extensions and MCP servers too. | ❌ FALSE | “Its file and shell tools run in a microVM; extensions and local MCP servers still run on the host.” Sandboxes additionally require “macOS on Apple Silicon, or Linux with access to `/dev/kvm`.” |
| The agent's shell commands inherit your API keys. | ❌ FALSE | “Mirror does keep its own provider API keys, such as `REFLECTION_API_KEY`, out of the environment of commands the agent runs”; the reference lists all eight key variables as withheld. |
| Mirror sends prompts and code to Statsig. | ❌ FALSE | Analytics events record IDs, environment metadata, and “Names such as the slash command or tool used, and a prompt's length”; the “Never sent” column lists “Prompts and model responses,” “Code and file contents,” and “Tool arguments and output.” |
| Turning analytics off deletes pending events. | ❌ FALSE | “Turning analytics off leaves that folder as it is; delete it to remove unsent events” — `~/.mirror/analytics/` holds events, retried (and older-than-five-days dropped) on the next start with analytics on. |
| Debug logs are safe to attach publicly. | ❌ FALSE | “Don't share logs recorded with `--log-level debug`: they include request headers, which contain your API key.” |
| `/feedback` attaches the conversation and logs automatically. | ❌ FALSE | It opens “a public GitHub issue form after confirmation. Nothing is attached or submitted automatically,” and issues are public — review any attached logs first. |
| `CLAUDE.md`-style instruction caps apply per file. | ❌ FALSE | The 32 KiB budget is global: “Mirror reads at most 32 KiB of instructions in total and truncates the rest.” |
| Mirror's TUI runs on Windows terminals via WSL-like shims natively. | ⚠️ PARTIAL | There is no native Windows build; the coding-agents quickstart only offers WSL for the other agents it documents, and Mirror's own docs list only macOS 14+ Apple Silicon and Linux glibc 2.28+. |
