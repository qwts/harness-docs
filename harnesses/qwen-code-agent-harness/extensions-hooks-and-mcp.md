# Extensions, hooks, and MCP

**Verified:** 2026-11-16 (Qwen Code 0.27.4 npm latest; docs site main)

## Extensions

“Qwen Code extensions package prompts, MCP servers, subagents, skills and custom commands into a familiar and user-friendly format.” Compatibility: “Extensions and plugins from Gemini CLI Extensions Gallery, Claude Code Marketplace, Qoder, and the portable Agent Plugins v1 format can be directly installed into Qwen Code.” Claude plugins are auto-converted: “`claude-plugin.json` is converted to `qwen-extension.json`”; “Agent configurations are converted to Qwen subagent format”; “Skill configurations are converted to Qwen skill format”; “Tool mappings are automatically handled.”

Management: `qwen extensions install|link|list|enable|disable|update|uninstall` and `qwen extensions sources`; in-session `/extensions` opens “an interactive manager with three tabs” (**Discover**, **Installed** grouped by scope, **Sources**) with hot reload — “Changes made here hot-reload immediately, without restarting Qwen Code”; CLI-command changes apply “on restart.” Install sources: git URL, local path, archive/archive URL, npm package, marketplace. `--extensions`/`-e` selects extensions for a session; “`qwen -e none` to disable all extensions.” Untrusted folders block extension management (“You **cannot install, update, or uninstall** extensions”).

Extension capabilities include MCP servers, slash commands, subagents, skills, an extension context file (`contextFileName`, concatenated into every request), and conditional-only `rules/`. Extension rules “are labelled by their owner in the prompt — `charts:rules/charting.md`, not a path climbing out of the project.”

**Agent Plugins v1** — “Qwen Code natively loads portable Agent Plugins v1 packages. The package keeps its standard `plugin.json`, `mcp.json`, and `SKILL.md` files: installation does not generate `qwen-extension.json` or rewrite portable files.” Support matrix: direct-child `skills/*/SKILL.md` yes; stdio and streamable HTTP MCP yes; “Legacy HTTP+SSE MCP servers”: “No; the entry is skipped”; “Commands, agents, and hooks”: “No; these directories are ignored.” “For stdio MCP servers, Qwen Code expands `${PLUGIN_ROOT}` and `${PLUGIN_DATA}` once in `args`, environment values, and `cwd`. … Remote MCP endpoints must use HTTPS, except for loopback HTTP endpoints.” “The experimental `allowed-tools` field is recognized as a string but does not grant pre-approved Qwen tools.”

**Mods (experimental)** — “Qwen Code can run a small subset of the Claude Code Mod API in headless and interactive terminal sessions. This feature is opt-in and requires a trusted workspace and an enabled Claude or native Qwen extension.” Enable with `/settings` → “**Mods (Experimental)**” or `"experimental": {"mods": true}`; “Agent Plugins v1 packages continue to ignore hooks.” Mod packages use `.claude-plugin/plugin.json` plus `hooks/hooks.json` and JS modules with `on('session.start'|'command.run', ...)` handlers.

## Hooks

“Qwen Code hooks provide a powerful mechanism for extending and customizing the behavior of the Qwen Code application … **Hooks are enabled by default.** You can temporarily disable all hooks by setting `disableAllHooks` to `true` in your settings file.”

Four executor types: `command` — “Execute a shell command. Receives JSON via `stdin`, returns results via `stdout`”; `http` — “Send JSON as a `POST` request body to a specified URL”; `function` — “Directly call a registered JavaScript function (session-level hooks only)”; `prompt` — “Use an LLM to evaluate hook input and return a decision.”

24 events, each with a documented matcher target: `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart` (source `startup`/`resume`/`clear`/`compact`), `SessionEnd` (reason `clear`/`logout`/`prompt_input_exit`/…), `SessionDelete`, `MessageDisplay`, `Stop`, `StopFailure` (error type `rate_limit`/`server_error`/`loop_detected`/…), `SubagentStart`/`SubagentStop` (agent type), `PreCompact`/`PostCompact` (`manual`/`auto`), `Notification` (`permission_prompt`/`idle_prompt`/`auth_success`), `PermissionRequest`, `PermissionDenied` (“When AUTO-mode classification denies a tool call”), `TodoCreated`/`TodoCompleted`, `InstructionsLoaded`, `FileChanged`.

“`matcher` is a regular expression used to filter trigger conditions.” Matching rules: `""`/`"*"`/`".*"` match all; “In a `|`-separated list … the matcher matches when any entry … is `*`, `.*`, or exactly the value, unless the whole matcher starts with `^` or `(`”; otherwise “the matcher is an unanchored regular expression … Because the expression is unanchored, `read` also matches `read_file`.” “Built-in display names such as `WriteFile` and `ReadFile` are also accepted as matcher aliases … and so are the tool names permission rules accept, including Claude Code's `Bash`, `Read` and `Write`.” `PreToolUse` supports “Replacing the tool input.”

Loading and trust policy: project hooks (from the project's `.qwen/settings.json`) run only with “your **approval of the exact configuration** … or **explicit folder trust**” — “While a block awaits its first decision it is withheld and the interactive approval dialog asks … A reload that changes the project hooks asks for approval again.” “Project skill and agent frontmatter hooks require **explicit folder trust** … Disabling folder trust does not authorize frontmatter hooks, including in YOLO mode. Their instructions still load.” Hooks declared in an agent's frontmatter “apply only to that invocation … They do not inherit into nested agents or run for parents and siblings.” “Run `/hooks` to open a read-only browser of the hooks this session runs … Opening the interactive menu reloads hook definitions from the user, workspace and system … settings files used by this session … Reloading requires this explicit menu-open action.” Controls — “`disableAllHooks`, `stopHookBlockingCap`, `security.allowedHttpHookUrls`, `security.allowPrivateNetworkHooks` and `security.folderTrust` … still require a restart.” HTTP hooks can reach private networks only via “Allowing private-network hooks (managed environments only).”

## MCP

“Qwen Code loads MCP servers from `mcpServers` in your `settings.json`.” Scopes: “**User scope (default)**: `~/.qwen/settings.json` across all projects on your machine”; “**Project scope**: `.qwen/settings.json` in your project root”; plus the system layers. CLI: `qwen mcp add [--scope user|project] [--transport http|sse|stdio] ...`, `qwen mcp remove`; in-session `/mcp` — “open the MCP management dialog to view and manage servers.” Transports: `http` (“streamable HTTP”; JSON field `httpUrl`), `sse` (“Legacy/deprecated”; field `url`), `stdio` (`command`, `args`, optional `cwd`, `env`). “If a server supports both, prefer **HTTP** over **SSE**.” “If multiple are specified, the order of precedence is `httpUrl`, then `url`, then `command`.” Name collisions get server-alias prefixes (“`serverAlias__actualToolName`”). Per-server options include `headers`, `timeout`, `trust`, `description`, `includeTools`/`excludeTools` (“**Note:** `excludeTools` takes precedence over `includeTools`”), and `discoveryTimeoutMs`. Global allow/deny lists (`tools.disabled`, etc.) and tool filtering per server are documented under “Tool filtering”.

Progressive discovery: “Qwen Code discovers MCP servers in the background after the UI is already interactive … the model's tool list updates within roughly one frame (~16 ms) of each server completing its discover handshake.” Headless “still waits for MCP discovery to settle before sending the first prompt.” Rollback escape hatch: `QWEN_CODE_LEGACY_MCP_BLOCKING=1` — “restore the pre-progressive-MCP behavior where `Config.initialize()` waits synchronously for every configured MCP server's discover handshake before returning.”

Beyond tools: “Any prompt a server advertises via `prompts/list` becomes an executable **slash command**”; resources are browsable via `/mcp` and injectable with “the `@server:uri` syntax … On submit, the referenced resource is read and its contents are appended to your message … Resource reads are disabled in untrusted folders.”

Safety: “**Server trust** (`trust: true`): bypasses confirmation prompts for that server only in a trusted workspace (use sparingly).” Connection-loss replay: “Qwen Code only reconnects and replays the current MCP tool call when the server has `trust: true`, the workspace is trusted, and the tool explicitly declares either `idempotentHint: true` or a consistent read-only annotation.” “Annotations are server-provided behavior hints, not permissions or an authorization boundary.” OAuth: “Qwen Code supports OAuth 2.0 authentication for MCP servers”; default redirect “`http://localhost:7777/oauth/callback`”; remote deployments configure `--oauth-redirect-uri` with “a public URL ending in `/oauth/callback`” reverse-proxied to the local callback — “Qwen Code does not terminate TLS.” MCP App resource limits are documented in the reference section.
