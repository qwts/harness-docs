# Subagents, skills, teams, and goals

**Verified:** 2026-11-16 (Qwen Code 0.27.4 npm latest; docs site main)

## Subagents

“Subagents are specialized AI assistants that handle specific types of tasks within Qwen Code”; they “maintain their own conversation history, separate from your main chat.” The Agent tool is `task` (permission alias `Agent`). Precedence for backgrounding: “An explicit `run_in_background` argument takes precedence over the agent definition's `background` field, which takes precedence over this setting” (`agents.defaultBackground`, default `true` — background). Results: “Background runs send a completion notification containing the result to the main conversation; foreground regular subagents return results inline”; `list_agents` finds background agents and `send_message` continues one. The built-in Explore subagent's model is set by `agents.builtin.exploreModel` (default `inherit`); `agents.modelGrades`/`allowedGrades` map and whitelist semantic model grades.

**Fork subagent** (`subagent_type: "fork"`): “A fork inherits the parent's full conversation context and normally runs detached in the background.” Only forks accept `fork_turns` (“A positive integer string such as `"3"` inherits the most recent three real user turns”), `fork_tools` (“exact canonical tool names … or MCP server patterns such as `mcp__github`; … a call not matched by `fork_tools` is rejected before scheduling or approval”; forks never execute `ask_user_question`; `*` is not accepted), and `fork_profile` (named restrictions saved in `.qwen/fork-profiles/<name>.md`, “cannot exceed 64 KiB”, project-only, `promptHint` ≤ 200 chars). “All forks share the parent's exact API request prefix … enabling DashScope prompt cache hits.” “Fork children cannot spawn any further sub-agent.” “**No worktree isolation**: Forks share the parent's working directory.”

**External executors:** “The built-in `claude-code` and `codex` agents delegate to separately installed native tools. Install and authenticate Claude Code with its `claude-agent-acp` adapter, or Codex with its `codex` executable … Qwen Code does not fall back to its own model when the executable is missing.” Claude Code “uses the ACP executor and supports continued input while its session is retained”; Codex “uses an ephemeral app-server thread for a single task … Codex tasks cannot receive messages or resume.” Codex sandboxing: “Without an agent override, default, plan, and auto sessions use a read-only sandbox; Qwen's AUTO classifier does not inspect native commands. Intermediate Qwen subagent modes do not grant native access during nested delegation. Explicitly select auto-edit in the session or Codex agent definition to allow workspace writes and unattended workspace commands, or yolo for full access.” A custom agent sets frontmatter `executor: {kind: codex|acp, command: ...}`; “Qwen model overrides, tool lists, subagent hooks, `maxTurns`, fork history, teams, and workflows are not supported for external executors.” Both “require a trusted workspace and are unavailable in safe mode.”

## Agent Team, Arena, and Agent Board

- **Agent Team** (experimental): “Set `experimental.agentTeam` to `true` … or start Qwen Code with `QWEN_CODE_ENABLE_AGENT_TEAM=1`.” `/coordinate` “creates a team, assigns up to three independent workstreams, and uses the existing team tools for messages and task state” (the `experimental.agentTeam` toggle enables “`team_create`, `task_create`, `task_update`, `send_message`, etc.”). “Read-only teammates cannot execute shell commands or write files. If implementation is needed, the leader can create one Git worktree and pin one writer teammate to it; the leader remains the only merge authority.”
- **Agent Arena** (experimental): “Dispatch multiple AI models simultaneously to execute the same task”; “Each model runs as a fully independent agent in its own isolated Git worktree”; `/arena --models qwen3.5-plus,glm-5,kimi-k2.5 "Refactor the authentication module to use JWT tokens"`; “you compare results and select a winner to merge back into your main workspace”; unlike subagents, “Agents do not collaborate.”
- **Agent Board** (experimental): “Agent Board lets independently started agents share work through files on the same machine. It does not start, join, monitor, or send input to agent processes.” Commands: `qwen board task|show|claim|done --board <name> --as <actor>`. “`--as` is a label recorded with the action, not authentication.”
- **Cross-session messaging** is covered on the sessions page.

Mode choice table: `/coordinate` with Agent Team — “Different workstreams contributing to one result”; Subagents — “Small delegated tasks”; Arena — “Several models competing on the same task”; Herdr — “Coordinating different CLI products or remote terminal sessions” (“External terminal-level control”).

## Skills

“Skills are modular capabilities that extend the model's effectiveness through organized folders containing instructions (and optionally scripts/resources). … Skills are **model-invoked** — the model autonomously decides when to use them based on your request and the Skill's description. This is different from slash commands, which are **user-invoked**.” Explicit invocation is `/<skill-name>` (the registered name; extension skills carry the owner — “`rust:pdf`, not `pdf`”). `/skills` “opens the Skills panel, where you can browse, search, toggle, and launch Skills interactively.”

Locations: personal `~/.qwen/skills/` and `~/.agents/skills/` (“If both folders contain a Skill with the same name, the one in `~/.qwen/skills/` wins”); project `.qwen/skills/` and `.agents/skills/` (same precedence rule). “**Generate a project Skill with `/learn`**” — “The command runs as a normal agent turn and creates the result under `.qwen/skills/learned-skill-<name>/SKILL.md` with `source: learned` in its frontmatter. Review the generated instructions before using or sharing them.” `/learn` accepts “local or direct-link `.mp4`, `.webm`, `.mov`, and `.m4v` videos … Video learning requires a video-capable model on an OpenAI-compatible provider. YouTube page URLs are not direct video input.” Skills follow the Agent Skills specification and can be gated on `paths:` (“which keeps even their listing entry out of the prompt until it is relevant”). Bundled skills exist too (“1.5 Built-in Skills” in the commands page), including `/loop`.

## Custom commands

Four command kinds: slash commands, @-commands introducing files, `!` shell commands, and custom commands (Markdown recommended, “TOML File Format (Deprecated)”). Custom-command parameter processing: “Context-aware Injection (`{{args}}`)”, “Default Parameter Processing”, “Shell Command Execution (`!{...}`)”, “File Content Injection (`@{...}`)”. `--disabled-slash-commands` (unioned with `slashCommands.disabled` and `QWEN_DISABLED_SLASH_COMMANDS`) hides commands.

Side features: `/btw` (“Side Question”), `/advisor` (“Second Opinion” — uses `advisorModel`), `/recap`, `/diff`, `/plan`, `/goal`, `/approval-mode`, `/permissions`, `/mcp`, `/extensions`, `/ide install`, `/settings`.

## Goals

“A Goal keeps Qwen Code working across turns until a stated condition is met. Set one with `/goal <objective>`, and the session keeps going on its own. When the model proposes that the objective is complete or blocked, an independent verifier judges that proposal.” “The verifier never runs commands. It judges from what is already in the transcript … (256 000 bytes, with any single record cut in the middle past 8 000).” “Printed text proves only that text was printed. A claim that tests pass, a file changed, or a remote is updated needs the corresponding tool result in the transcript.” When evidence is missing, “the verdict is "not yet", not "done".” Commands: `/goal`, `/goal set|edit|pause|resume|clear`, `/goal-draft`. “Creating, editing, or resuming a Goal requires a trusted workspace (`/trust`).” Budgets: `model.goalTokenBudget` (once a Goal has billed a turn, “the footer pill and every status card show what it has spent against the window it is allowed, as `1.2k/30.0m`”), plus off-by-default `model.goalMaxTurns` and `model.goalMaxActiveMinutes`; “Whichever window runs out first, the Goal gets the same single wind-down turn to hand off and then stops.” “Typing a message while a Goal is active does not pause it. Your message runs as the next Goal turn.”
